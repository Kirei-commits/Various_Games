# ぐんぐん農園 — つぎにやること

迷ったら **「待ち時間が増えていないか」「1画面から溢れていないか」** で決める。
この2つを守れないものは、どれだけ面白くても入れない。

数値を触ったら `npm run simulate` で測り直し、`tests/logic/economy.test.mjs` の
閾値も更新する（**実測より下に置く**）。

---

## 自己レビューと市場調査でわかったこと（2026-09-13）

作り終わった時点で一度手を止めて、「これは面白いゲームになっているか」を調べた。
結論は **まだなっていない**。よく出来てはいるが、面白さの芯がまだ足りない。

### 調べたこと

元のゲーム（Hay Day）で**待ち時間が何をしていたのか**を調べると、
待ちは「不便」ではなく**構造**だった。

- 待ちがプレイヤーを呼び戻す装置になっていて、課金の動機にもなっている
  （[Hay Day monetization analysis](https://www.blog.udonis.co/mobile-marketing/mobile-games/hay-day-monetization)）
- 1日に10分×3回のほうが30分×1回より7割速く進む設計になっている。
  つまり**待ちがセッションの形を決めていた**
  （[Hay Day gameplay systems](https://medium.com/@hoangvm11.mac/leveling-up-your-game-unlocking-monetization-through-analyzing-hay-day-gameplay-systems-with-4165f47da0dc)）

**待ちを抜くなら、待ちがやっていた仕事を別のもので埋めなければならない。**
放置ゲームの設計論が言っているのはそこで、

- 「どのクリックにも戦略的な意味を持たせる」
- 「ある設備を上げると別の設備が苦しくなる——そのつながりが飽きを防ぐ」
  （[Idle game design](https://games.themindstudios.com/post/idle-clicker-game-design-and-monetization/) /
   [Top idle mechanics](https://mobilefreetoplay.com/top-7-idle-game-mechanics/)）

農業ゲームの不満として最もよく挙がるのも、まさに
**「1マスずつ収穫して植え直すのがひたすら面倒」**だった
（[farming games discussion](https://www.gamedeveloper.com/game-platforms/why-players-become-obsessed-with-farming-games-)）。

### 測ったこと

10分×6回を自動で回し、**プレイヤーの操作を種類ごとに数えた**。

| | 改修前 | 改修後 |
| --- | ---: | ---: |
| 収穫・植え直し（往復） | **71%** | — |
| リズムの操作（2つの大ボタン） | — | 75% |
| 判断のある操作（配達・売買・断り・タネ替え） | **11.5%** | **24.9%** |

**操作の9割近くに判断が無かった。** 待ちが無いぶん手数だけが増え、
「考えるところ」は注文と店に少し残っているだけだった。

### 直したこと その1（済）

**収穫と植え直しを1タップにまとめた。** 待ちのあるゲームでは
「収穫する → 何を植えるか決める」が意味のある間になるが、待ちが無いと
**ただの往復**になる。収穫すると選んでいるタネがその場に植え直される形にした。
副ボタンも「取り出す＋余った材料で全部仕込む」を1タップにまとめ、
**注文が欲しがっている材料には手を出さない**ようにした（押すのが怖いボタンにしない）。

判断のある操作の割合は 11.5% → 24.9% になった。育ちの速さは変えていない
（10分でレベル14・詰まり0ms・救済0回）。

### 直したこと その2 — 待ち時間を実際に測って潰した（済）

「待ち時間が限りなく0に近い」を名乗るなら測れる形にすべきなので、
**手持ち無沙汰の時間**（収穫・植える・取り出す・仕込む・届ける のどれも無い時間）を
100ミリ秒きざみで測った。上限を10秒にしても、**畑が一斉に実って一斉に空く**ので
「全部タップ → 数秒なにもできない」の繰り返しになっていた。

**時間差まき**を入れた。まとめて k マス植えるとき、j 番目が `sec * (j+1)/k` で実る。
畑は順番に実り続け、いつ見ても収穫できるものがある。
**どの畑も作物の秒数より長くは待たせない**ので、10秒の約束は保たれる。

| | 前 | 後 |
| --- | ---: | ---: |
| 手持ち無沙汰の割合 | 28.1% | **14.1%** |
| **1秒以上つづいた待ち**（人が待ったと感じるところ） | **8.1%** | **0.1%** |
| いちばん長く待たされた時間 | 3500ms | **1300ms** |

畑の回転が1.38倍になったので、経験値カーブを実測から引き直した
（`42*level^1.35` → `58*level^1.35`）。育ちの速さは元どおり（10分でレベル14、
レベル20まで約18分）。この数字は `npm run simulate` が毎回出し、
**3秒を超えたら失敗する**ようにしてある。

### 直したこと その3 — レベルに沿って増え続けるようにした（済）

数えたら **Lv14〜20 の7レベル連続で何も解放されなかった**。18分の進行のうち、
後半8分が「新しいものが何も出てこない」時間になっていた。

- 作物を3種（🍅トマト Lv14 / 🫒オリーブ Lv16 / 🍈メロン Lv18）
- 施設を7台（🥫ケチャップ工場 → 🍝パスタ工房 → 🧴オリーブ油しぼり →
  🍕ピザ窯 → 🍨アイス屋 → 🥗サラダバー → 🥪サンド屋）

足したのは「格上のこむぎ」ではなく**鎖の続き**。ピザは
こむぎこ + チーズ + ケチャップ の4段目で、前半に作った品がそのまま材料になる。

**同じ穴が二度と開かないように lint が見張る**（2レベル以上つづけて空なら失敗）。
作物11種・施設18台・品物29種。25分でレベル20に届き、18台中17台まで買える。

### 直したこと その4 — タネ選びを本物の判断にした（済）

1秒あたりの儲けも1枠の値打ちも**両方とも格上が勝つ**表になっていて、
解放された中でいちばん格上を選べば常に正解だった。タネの一覧はただの飾りで、
レベルが選択を代行していた。価格表を規則から組み直した。

- **1秒あたりの儲け**: こむぎ 4.00 → メロン 2.11（**短いほど良い**）
- **1枠の値打ち**: こむぎ 11 → メロン 91（**長いほど高い**）
- 同じ秒数の作物は、タネ代と売値に**同じ額**を足して差をつける
  （儲けは据え置きで倉庫の持ちだけ良くなる = 上位作物のごほうび）

時間差まきのおかげで「長い作物 = 実る間隔が空く = 手が空く」が本当になったので、
この取引が効く。同じ手順で作物だけ変えて10分回した実測:

| 作戦 | 稼ぎ | 経験値 | 収穫の手数 |
| --- | ---: | ---: | ---: |
| 短いのだけ | 48,407 | 6,009 | **3,000回** |
| 長いのだけ | 37,902 | 6,772 | **800回** |

短いほうが稼ぎ1.28倍、ただし手数3.75倍。長いほうは経験値1.13倍で手数は4分の1。
**どちらも全部では勝たない。** lint が単調性を、ロジックテストがこの比較を毎回確かめる。

コインの目方が約2倍になったので、施設・畑・倉庫の値段も2倍にした。
育ちの速さは据え置き（10分でレベル14〜15、レベル20まで約17分半、25分で施設18台）。

### 直したこと その5 — 注文を主筋にした（ふなびん）（済）

コインの出どころを数えたら、**稼ぎの55%が「余りを売っただけ」**だった。
届けるより売るほうが主筋で、注文はおまけになっていた。

原因は単価ではなく**量**。注文1件は売値の1.35倍払うので率は良いが、
3枠が吸える量は農園が10分で産む約4,600個のうち200個ほどしかない。
残りは売るしかない。**枠を大きくしても解決しなかった**——1件が大きくなって
件数が半分になるだけ（10分で67件 → 35件）。

**ふなびん**を入れた。ふつうの注文との違いは3つ。

- **少しずつ積める。** 揃うまで抱えておかなくていいので、余ったそばから積める
- **安いものをたくさん運ぶ。** 船が運ぶのは余り物。最初に高い品へ寄せたら
  ケーキ×11 のような船が出て、**10分で一度も出港しなかった**
- **積みきると2.2倍。** 間に合わなくても積んだぶんは売値で引き取られる（丸損させない）

| コインの出どころ（10分） | 前 | 後 |
| --- | ---: | ---: |
| ふつうの注文 | 44.6% | 40.3% |
| ふなびん | — | 25.5% |
| **注文ぜんぶ** | **44.6%** | **65.8%** |
| 余りを売る | 55.4% | **34.2%** |

副産物として、手持ち無沙汰が 17% → 11.4% に減った（積む作業が常にあるため）。
船は「何を植えるか」の理由にもなり、タネ選びの取引と噛み合っている。

**通しプレイが UI と engine のズレを捕まえた。** ボタンの出し分けを
「倉庫に在庫があるか」で書き、実際に積む処理は「注文のぶんを引いた余り」を見ていた。
押せるのに何も積めないボタンになっていた（積んだ数 0）。
判定を `Engine.boatLoadable()` に一本化した。
通しプレイに `--level` を足して、後半の画面も踏むようにしてある
（最初から回すと3分でレベル4までしか行かず、ふなびんを一度も見ない）。

### 直したこと その6 — 手応えと、一日の色（済）

- **連打が損だと伝える。** まとまって穫れたときに「まとめるほど つぎが早く実る」と出す
  （毎回言うとうるさいので、畑の半分以上がまとまったときだけ）
- **収穫の音が段を上がる。** 半音ずつ8段、途切れると戻る。
  数千回繰り返す操作なので、同じ音が続くより段を上がるほうが手応えが出る
- **穫ったものが倉庫めがけて飛ぶ。** 受け取った側も弾む。粒は最大5つまで
- **一日が3分で一巡する。** 朝→昼→夕→夜。待たせないぶん一日も速く回せる。
  夕を橙に振ると**土の色と近づいて畑が読めなくなった**ので、桃〜藤にしてある。
  昼と夜には平らな時間を作る（ずっと補間していると灰色の帯が居座る）

**古い保存が静かに壊れていたのも直した。** ふなびんで state の項目が増えたが、
既に保存されている農園には無く、`now >= undefined` が常に false で
**船が永久に来なかった**（`stats.shipped` は NaN）。`Engine.normalize()` が
`create({bare:true})` から形を借りて埋める——項目を増やすたびに書き足す必要はない。

### 直したこと その7 — 実績（済）

レベル20に着いたあと目標が無かったので、15個の実績を足した。
収穫・加工・配達・出港・レベル・施設・畑・コインの8種類を数える。
メニューに並び、進み具合が見える。25分回して半分強が取れる程度に置いてある
（全部取れてしまうと長く遊ぶ理由が残らない。テストで両側を見ている）。

実績の知らせを ticker に出したら、収穫の知らせを押しのけた。
レベルアップと同じ**操作を止めない浮き札**にしてある。

### 直したこと その8 — きょうの作物（済）

待ちが無いぶん、**同じ輪をひたすら回す**ことになりやすい。
空の色しか意味の無かった一日（3分）に、遊びの意味を持たせた。
**一日ごとに作物がひとつ選ばれ、もうけが1.5倍**になる。
3分ごとに「いま何を植えるのが得か」がずれるので、手なりが通らなくなる。

**売値そのものを1.5倍にしてはいけなかった。** タネ代の高い作物ほど得が大きくなり、
メロンはもうけが3.4倍になって、**1秒あたりでも1枠の値打ちでも最強**になる。
それはタネ選びが飾りに戻るということ。もうけ（売値−タネ代）に掛けると、
どの作物も一律1.5倍になって、短い・長いの取引はそのまま残る。

| | 1秒あたり（ふだん） | 1秒あたり（きょうの作物） | 1枠の値打ち |
| --- | ---: | ---: | ---: |
| 🌾こむぎ（2秒） | 4.00 | **6.00** | 11 → 15 |
| 🍇ぶどう（9秒） | 2.11 | **3.22** | 45 → 55 |
| 🍈メロン（9秒） | 2.11 | **3.22** | 91 → 101 |

倍率が乗っても、メロン（3.22）は素のこむぎ（4.00）に1秒あたりでは勝てない。
「きょうの作物だから必ず正解」にはならず、**ふだんの順位を少し入れ替えるだけ**になる。

**計測を壊しかけた。** 最初は共有の乱数から引いていたが、そうすると注文の抽選がずれて、
「手を動かす間隔だけを変えて比べる」計測が**条件ごとに違う作物を掴んだ**
（400ms だけ3割落ちたように見えた）。日数からの撹拌で決めるようにして直した。

10分の実測は レベル14〜15・稼ぎ 70,467（前 69,943）で、育ちの速さは変わっていない。

### 直したこと その9 — 注文の枠をレベルで増やした（済）

コインの出どころを**測れるようにした**（`npm run simulate` が毎回出す）ら、
**主筋が静かに入れ替わっていた**ことが分かった。

| | 10分 | 25分 |
| --- | ---: | ---: |
| 注文ぜんぶ（枠3つのまま） | 67.1% | **50.6%** |
| 余りを売る | 44% | **51.2%** |

ふなびんで直したはずの「稼ぎの半分が売却」に、**後半だけ戻っていた**。
原因は単価ではなく**受け皿**で、農園はレベルで3倍に育つのに
**注文の枠だけが3つに固定**されていた。25分の配達は61件——
10分の44件から、15分かけて17件しか増えていない。

枠を実測で振って決めた（25分）。

| 枠 | 配達 | 注文ぜんぶ | 余りを売る |
| ---: | ---: | ---: | ---: |
| 3 | 61 | 54% | 55.8% |
| 4 | 69 | 58% | 45.1% |
| **5** | **78** | **60%** | **39.8%** |
| 6 | 98 | 60% | 41.8% |

6枠にしてもふなびんの取り分を食うだけで、注文ぜんぶの割合は伸びない。
**3 → Lv8で4 → Lv15で5** にした（レベルアップの知らせにも出る）。
結果は 10分 72.4% / 25分 59.2%。育ちの速さと待ち時間は変わっていない。

**生産側だけを増やすと、この比率は必ず崩れる。** 作物や施設を足したときは、
注文が吸える量も足りているかを測り直す。ロジックテストが両方の時間で見張る。

## A. 面白さの芯（最優先）

### 1. 通しプレイの方策が弱かった（測り方の問題だった）— 直した

「加工と注文に手が回っていない」「実ブラウザだと注文が揃いにくい」と見ていたが、
**通しプレイの方策が注文を見ていなかっただけ**だった。
植えるタネを「開いている注文 → ふなびん → 格上」の順に選ぶようにしたら:

| 3分（最初から） | 前 | 後 |
| --- | ---: | ---: |
| 配達 | 2件 | **10件** |
| 加工 | 3回 | **22回** |
| 最高コンボ | 1 | **10** |

Lv12から2分の回も 配達 0〜2件 → 2〜5件 になった。
**ゲームではなく測り方を直した。** 通しプレイの結果を読むときは、
方策がその要素を触っているかを先に確かめる。

### 2. 畑の手数 — 測ったら、思っていたより問題ではなかった

通しプレイでは収穫の回数が加工・配達より桁ひとつ多く、「畑に手数を取られすぎ」に見えた。
**手を動かす間隔だけを変えて測ったら、話が違った。**

| 間隔 | 10分の稼ぎ | 手数 | 最速の人と比べて |
| --- | ---: | ---: | ---: |
| 200ms | 56,843 | 2,239 | 100% |
| 400ms | 69,783 | 1,425 | 123% |
| **800ms** | **76,387** | **746** | **134%** |
| 1500ms | 62,686 | 400 | 110% |
| 3000ms | 37,546 | 200 | 66% |

**連打はいちばん損。** いちばん良いのは毎秒1回くらいで、そのとき手数は3分の1になる。
時間差まきが「まとめて収穫するほど次が早い」性質を生んでいたため
（k マスまとめて蒔くと平均 `sec*(k+1)/(2k)` で実る）。

つまり手数が多いのは**速く叩くことを選んだ場合だけ**で、押しつけられてはいない。
400〜1500ms のどこでも110〜134%と幅が広く、狙って合わせる必要もない。
この性質はテストで守る（連打がいちばん得になったら失敗）。

残る改善は「連打しても損だと**プレイヤーが分かる**か」。
いまは数字にしか出ない。まとめて収穫したときに手応えを返すなど、
**伝え方**の問題として扱う。

### 3. 人が遊んだときのペース — 測った（済）

ほかの計測はぜんぶ「400ミリ秒おきに休まず触り続ける」前提だった。
人らしい手の動き（ふだん 550〜1100ms、ときどき考える間とよそ見）で測り直した。
`npm run simulate:human` でいつでも出せる。

| | 手を止めない | 人らしい手つき |
| --- | ---: | ---: |
| 1分あたりの手数 | 150 | **52**（毎秒1回くらい） |
| 3分 | — | **Lv7** |
| 10分 | Lv14〜15 | **Lv13** |
| 25分 | Lv20 | **Lv20** |

**差は10分で1〜2レベル、25分では無い。**
速く叩けるほど有利、にはなっていない（時間差まきのおかげで連打が損になるため）。
ここは触るたびに測り直す——ロジックテストが人の手つきでも
「救済0回」「待ち3秒以下」「25分でLv17以上」を見張る。

なお 3分チャレンジがちょうど Lv7 で終わるのは、ふなびんの解放レベルと同じ。
**あの3分は、ふなびんが来る手前までの腕くらべ**になっている。

### 4. ふなびんが来るまでが長い — 測ったら、そうでもなかった

解放レベルを 4 / 5 / 6 / 7 に振って5分ずつ測った。**ほとんど変わらない。**

| 来はじめ | 出港 | 注文ぜんぶ | 余りを売る |
| --- | ---: | ---: | ---: |
| Lv4（56秒） | 2 | 83.4% | 26.6% |
| Lv5（80秒） | 1 | 79.4% | 31.3% |
| Lv6（106秒） | 1 | 88.8% | 31.2% |
| **Lv7（142秒）** | 1 | 76.5% | 27.8% |

序盤は生産量そのものが少ないので、船を早く出しても積むものが無い。
**最初の2分半は、レベルと施設が次々に増える時間でもある**ので、
そこに船まで足すと覚えることが増えるだけだった。Lv7 のままにする。

### 4.5 ただし、この調べもので**本物の不具合**が出た（直した）

3分チャレンジは Lv7 に 2分22秒で着く。**残り38秒で船が来る。**
船の期限はいちばん短くても3分なので、**どうやっても満載にならない。**
それだけなら「進まない進捗バー」で済むが、

**積んだぶんは倉庫から引かれている。** 時計が止まると船ごと消えるので、
終わりぎわに積んだ人だけが丸損する——**積むのが罰になっていた。**

直しかたは「終了時に精算する」ではなく、**出港できない船を出さない**にした。
そうすると `expiresAt <= limit` が必ず成り立ち、
「終わる前に必ず期限切れの精算が通る」がタダで付いてくる
（終了時の精算を足すと、到達しない分岐が1本増えるだけになる）。
3分チャレンジに船は出ない——**あれは序盤の腕くらべ**で、施設も2〜3台しか出ない。

## B. 遊びの幅

## やらないと決めたこと

- **課金で待ち時間を飛ばす仕組み。** 元のゲームの待ちを消したのが出発点なので、
  「待ちを金で買う」構造そのものを持ち込まない
- **自動で収穫・自動で売る。** 資源のやりくりが消えて、畑を眺めるだけになる。
  （**植え直しの自動化は別の話**。あれは判断ではなく往復だったので畳んだ）
- **10秒を超える作物・加工品。** どんなに強くても入れない
- **「格上のこむぎ」を足すこと。** 新しい作物は、1秒あたりか1枠の値打ちの
  どちらかを譲る。両方で勝つものを足すと、その下が全部いらなくなる
- **時間差まきを「ずらして遅くする」方向に使うこと。** いちばん遅い1マスが
  作物の秒数ちょうどになるように、**短くする方向にだけ**ずらす。
  遅くする方向に倒すと10秒の約束が壊れる
