# 練習銀行アカデミー（仮称）

新卒〜中堅のエンジニアが、基礎力を失わずに **AI前提の開発プロセス（仕様 → AI実装 → 検証 → 運用）** を段階的に身につけるための練習アプリです。
架空の銀行アプリ「練習銀行」を、単元を進めながら自分のリポジトリで育てていきます。

仕様の出典は「アプリ開発練習アプリ 仕様プロンプト v0.1」。実装上の判断・要件との対応・未決事項は [SPEC-NOTES.md](./SPEC-NOTES.md) にあります。

## 遊び方

`index.html` をブラウザで開くだけです（サーバー不要・実行時の依存ゼロ。TypeScript を選んだときだけコンパイラを CDN から読み込みます）。GitHub Pages でも公開します。

1. **オンボーディング** — 5問の自己評価から、開始レベルと最初の単元を提案
2. 単元ごとに同じ5ステップ（L3 は実践ステップの進め方が変わる。下の表を参照）
   1. **理解（AIオフ）** 概念を読み、予測問題に答える
   2. **練習（AIオフ）** パーソンズ → 穴埋め → 修正 → ゼロから、の4段階。テストが通るまで
   3. **説明ゲート** 「何をするか」「どこが危ないか」を書く。合格すると AI が解禁
   4. **実践（AIオン）** 仕様を書いて AI に実装させ、差分をレビューし、テストで検証。説明してから取り込み、コミット → PR → CI → マージ
   5. **振り返り** AIオフ／オンの所要時間・失敗数・ヒント数・質問数を、事前の体感と並べて見る
3. マージしたコードはホームの「練習銀行」（スマホの銀行アプリ風の画面）で実際に動き、銀行が育っていきます。AI の解禁・マージ・修了ではお祝いの演出と効果音（設定で切れる。失敗では鳴らない）

## 研修ハッカソン（読む・レビューするモード）

「書けなくても、読めればいい・レビューできればいい」に特化したモードです。新卒1年目の主人公が、研修ハッカソンの6人のアジャイルチーム（スクラムマスターは毎スプリント交代）で、練習銀行の新サービス「AIお金相談チャット」を **24スプリント** でリリースします。

- 問題はすべて読解: 同期のコードをレビュー（行を選んで種類を付ける）／自分のコードのバグの行と直し方を選ぶ／コンフリクトを解く／動きを予想する／レビューコメントを書く／関係者（PO・ユーザー・技術ユーザー・法務・営業・セキュリティ室・役員）の割り込みに答える
- コードは React・JavaScript（画面）、Python（AI のサービス）、Java（勘定系 API）。動かしません
- スプリントの最初に「この章で使う知識」が配られ、終わるとレトロスペクティブ
- 登場人物とは選択肢で話せます（Claude の API キーがあれば自由チャットも。送信前の検査と AI 利用ログは単元と同じ）。名前は仮で、設定で変えられます
- ハッカソンの外の同期・友人・先輩もいます。分からない分野が出てきたら「🤔 聞きに行く」で知識を教わり、毎日しゃべる同期とは「☕ 今日の雑談」
- 登場人物の設定は [PERSONAS.md](./PERSONAS.md)（オーナー監修）

## 配属先モード（実案件・仕事の進め方）

ハッカソン（開発を学ぶ）と同時並行で、配属先の「モバイルバンキング開発グループ」で練習銀行のスマホアプリを運用しながら、開発チームを運営します。**1ターン＝1週間、全24週**。

- 毎週、チームの力（10ポイント）を「新機能・品質と負債の返済・運用と監視・休息と育成」に配分 → 今週の仕事 →（障害）→ 週報
- 今週の仕事で学ぶこと: 質問のしかた・チケットと完了の定義・進捗報告・要件ヒアリング・障害の第一報・設計書のレビュー・見積もり・議事録・遅延の報告・協力会社への依頼・コードレビュー・リリース判定・障害報告書・関係部署との調整・テスト計画・技術的負債の説明・運用設計・後輩の育成・優先順位付け・エスカレーション・改善提案・コスト感覚・目標設定・テックリード代理
- 障害はログを読んで原因の行と最初の対処を選ぶ／対応の順番を並べる／関係者に答える。分からなければ仲間に「聞きに行く」
- 数字（利用者・評価・技術的負債・チームの体力・社内の信頼・運用費）が週ごとに動き、上司がひとこと。ゲームオーバーはなく、24週後に年次評価

## モードのつながり

- ホームの **「今日やること」** に、ハッカソンの次の問題・今のスプリントで使う知識の予習（言語テキスト）・配属先の今週・今日の5問が並びます
- スプリントの資料から **予習できるテキストの章** へ、テキストの章の資料から関係するスプリントへ飛べます
- **称号**（15種）: 初レビュー・リリース！・ポリグロット・火消し見習い・1年目修了・バグハンター など。どのモードで条件を満たしても、次の画面でお祝いが出ます

## チャレンジ（腕試し）

ハッカソン・言語テキスト・配属先の問題から出題します。ヒントと「答えを見る」はなく、学習の記録には影響しません。

- **バグハント（無限）**: まちがえるまで続く。連続正解数の自己ベストを更新
- **今日の5問（デイリー）**: 日付で決まる5問。続けた日数を記録
- **言語ごと**: JavaScript・React・Java・Python・仕事の進め方で絞れる

## 言語テキスト（JavaScript・React・Java・Python）

「書けなくても読める」ようになるための読み物です。コードは動かさず、読んで答えます。

| コース | 先生役 | 章 |
|---|---|---|
| 🟨 JavaScript | 早乙女 ことは（先輩） | 値・型・演算子 ／ 関数・スコープ・クロージャ ／ 配列とオブジェクト ／ 非同期 ／ クラスと this ／ エラー処理とモジュール |
| ⚛️ React | 氷室 蓮（同期） | コンポーネントと JSX ／ props ／ state と useState ／ イベントとフォーム ／ useEffect と副作用 ／ リスト・key・条件付き表示とパフォーマンス |
| ☕ Java | 神崎 理央（同期） | クラスとコンストラクタ ／ カプセル化 ／ 継承とオーバーライド ／ インターフェースと抽象クラス ／ static・equals・hashCode ／ コレクションとジェネリクス ／ 例外 |
| 🐍 Python | 九条 学（同期） | 基本とインデント ／ リスト・辞書・内包表記 ／ 関数 ／ クラス ／ 例外と with ／ モジュール・デコレータ・非同期の入口 |

- 章の前に「この章に関係する単元（ハッカソンのスプリントなど）と、先に知っておくこと」の資料が配られます
- 節ごとに、登場人物の会話・図・例のコード・要点を読み、読解問題（動きの予想・バグの行と直し方・レビュー）に答えます（全133問）
- 章は順に開き、全問を終えるとバッジ。答えを見ずに全部解くと金のバッジ

## ヒントと「答えを見る」

ヒントは3〜5段階で、1つずつ開きます。**全部開けると「答えを見る」** が出て、答えを入れて先に進めます。答えを見た問題はホームの「答えを見た問題」に入り、自力で解き直すと消えます（練習で答えを見て解いた問題は「2問連続正解」には数えません。ハッカソンではポイントが半分）。理解ステップの予測問題は1度まちがえると答えを見られ、説明ゲートは2回出すと「お手本の観点」を開けます。

## 収録している単元

| レベル | 単元 |
|---|---|
| L1 新卒入門 | L1-01 金額を円で表示する ／ L1-02 残高を計算する ／ L1-03 ユーザーストーリーと受け入れ基準 ／ L1-04 単体テストを読み書きする ／ L1-05 小さなコミットとPR ／ L1-06 計算と表示を分ける ／ L1-07 秘密情報を画面やログに出さない ／ L1-08 ログを読む ／ L1-09 情報区分とAI利用ルール ／ L1-10 答えを写さずに質問する |
| L2 独り立ち | L2-01 AIなしでバグを直す ／ L2-02 入力を検証する ／ L2-03 二重送金を防ぐ ／ L2-04 AIが書いたPRの欠陥を見つける ／ L2-05 SQLインジェクションとXSSを理解する ／ L2-06 データを正規化する ／ L2-07 小さなPRに分けて、戻せるようにする ／ L2-08 障害の原因を特定する ／ L2-09 タスクを分解し、AIの差分を検証する ／ L2-10 LLMの出力を構造化して受け取る |

| L3 チームの中核（第2段階） | L3-01 仕様からAIに実装させる（振込予約）／ L3-02 AIのPRを本気でレビューする ／ L3-03 FAQボットへのプロンプトインジェクション ／ L3-04 リトライと縮退運転を設計する ／ L3-05 SLOとエラーバジェット |

L1・L2 で11領域のうち A〜K のすべてに単元があります（L1 は I を除く10領域）。

L3 の実践ステップは進め方が変わります。
- **spec-first ミッション**（L3-01・04・05）: EARS 記法の要件（自動判定）→ 設計を選ぶ → タスクに分ける → 要件IDつきのテスト → AI 実装 → 要件とテストの対応表（テストの無い要件を警告）
- **PR レビュー**（L3-02）: 欠陥を埋め込んだ AI の PR で、欠陥のある行を指摘して検出率で採点 → 直して取り込む
- **赤チーム演習**（L3-03）: 架空の FAQ ボットにプロンプトインジェクションを試し、入力・出力の両方で守る

「ダッシュボード」では、単元をまたいで AIオフ／オンの所要時間・失敗・ヒント・質問を比べられます。

## 課題の言語

既定は JavaScript です。設定で **TypeScript** を選ぶと、「ゼロから」の段階（strict）と実践のコードを型チェックしてから動かします。コンパイラ（TypeScript 5.6.3）は初めて使うときに jsDelivr から読み込みます。リポジトリと CI には、型を取り除いた JavaScript が入ります。

## AIチューター

- 標準は **ルールベースの疑似チューター**（無料・オフライン）。答えやコードは出さず、質問とヒントで導きます
- 設定で Claude の API キーを入れると、チューター・AI実装・説明の観点採点が本物の LLM（既定 Claude Opus 5.5、月の上限を超えたら Claude Haiku 5.5）になります
- AIへ送る前に、メールアドレス・電話番号・口座番号・カード番号・APIキーの形式を検査し、見つかったら送信を止めます
- AI の入出力はすべて「AI利用ログ」にハッシュの鎖つきで記録され、改ざんを検証できます

## 開発

```bash
npm ci
npm run lint        # 構文・読み込み順・外部参照・CSP・純粋なモジュール
npm run test:logic  # コンテンツ・採点・Git・チューター・評価セット（Node の標準テスト）
npm run test:e2e    # Playwright（デスクトップ + スマホ）
```

ブラウザを取得できない環境では `PW_CHROMIUM=/path/to/chrome npm run test:e2e`（リポジトリ直下の LOOP.md 参照）。
