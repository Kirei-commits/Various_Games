# CLAUDE.md — 理解度アップ・テストラリー

**えらんで答える10問**の理解度テスト。受講者はラリーを受け、講師は手持ちの資料からテストを作る。
既定は選択式（スマホでキーボードを出さずに解けることを優先）。記述式も残してあり、画面上部で切り替わる。
**ビルド不要・配信物の実行時依存ゼロ**。ES モジュールで書いてあるので `npm start` で開く
（`file://` では動かない。CORS で module が読めないため）。

## 構成

```
index.html              3つの画面（#screen-login / #screen-learner / #screen-teacher）
css/style.css           明るいテーマ。色は :root の変数だけで決まる
js/main.js              起動・役割の切り替え。持つ状態は data / registry / role の3つだけ

js/core/                題材を知らない中核
  judge.js              記述式の採点（正規化と照合）
  grade.js              A〜E の評価（減点表・レベル重み・閾値）
  hint.js               ヒントの段階
  banks.js              レベルの定義と、問題集の入れ物（createRegistry）
  choice.js             選択式の決まり（choices の先頭が正解／表示順を混ぜる）
  rally.js              単元の自動生成・レベルの階段・出題選定・進行
  store.js              localStorage（成績・作ったテスト・生成設定）

js/data/                同梱の問題集（純データ。default export）
js/author/              講師側
  extract.js            ファイル → テキスト（txt/md/csv/json/html/docx/pptx/xlsx/pdf/zip…）
  unzip.js              ZIP の展開（DecompressionStream）
  generate.js           この端末での問題生成
  llm.js                Claude 生成サーバーへの窓口（鍵はブラウザに置かない）
  validate.js           問題データの検査。**アプリも lint もここを呼ぶ**
js/ui/                  画面（dom / learner / teacher）
tools/studio.mjs        講師用ローカルサーバー。Claude 生成の API を足す（任意・配信しない）
```

## 開発コマンド

```bash
npm ci && npm test   # lint → ロジック → E2E
npm start            # http://127.0.0.1:8082/
npm run studio       # 同じポート ＋ /api/generate（ANTHROPIC_API_KEY が要る）
```

CI はリポジトリ直下の `.github/workflows/ci.yml`（3アプリを回す）。
**サブディレクトリ配下の `.github/workflows/` は GitHub では実行されない**。

## 壊してはいけない設計上の制約

1. **配信物に実行時の依存を増やさない。** ビルド工程も持ち込まない。
   Playwright と `@anthropic-ai/sdk` は開発時のみの依存で、`tools/` の外では使わない。
   Pages のワークフローが配るのは `index.html` / `css` / `js` だけ。
2. **ブラウザから Anthropic を直接叩かない。** API キーがページを開いた全員に配られる。
   Claude 生成は必ず `tools/studio.mjs` 越し。`js/author/llm.js` に鍵を持ち込まない。
3. **`localStorage` は必ず try/catch で包む。** 読み書きの両方が例外を投げうる。
   触るのは `js/core/store.js` の `storage()` だけ（テストは `useStorage()` で差し替える）。
4. **設定キーは必ず `Store.DEFAULTS` に定義する。** 定義漏れのキーは `merge()` で捨てられ、
   保存しても復元されない。
5. **乱数を直接呼ばない。** `Rally.seededRandom(seed)` を通す。`?seed=` で再現するため。
6. **`[hidden] { display: none !important; }` を消さない。**
   `.btn` などの display 指定が既定の `[hidden]` に勝ち、隠したボタンや画面が出たままになる。
   画面の出し分け（`showScreen`）もこれに乗っている。
7. **正規化で `=` と `+` を落とさない（`Judge.STRIP`）。**
   落とすと `==` が空文字になり、`contains()` が**何にでも一致する**。
   Java の等価性の単元がまるごと無意味になる。`contains()` の空 needle ガードも必ず残す。
8. **正誤は必須観点だけで決める。** 加点観点と誤解検出を正誤に混ぜない。
   混ぜると「加点を拾ったから通った」という説明のつかない正解が生まれ、
   画面の根拠表示（`.evidence`）が嘘になる。
9. **説明文を ui/ に書き足さない。** 『しくみ』パネルは
   `Rally.UNIT_RULES` / `LADDER_RULES` / `PICK_COST` / `SHUFFLE_RULES` /
   `Judge.RULE_TEXT` / `Grade.SCALE` / `Hint.STAGES` を**そのまま表に起こしている**。
   手書きの説明を足すと、定数を変えたときに説明だけが古くなる。
10. **ヒントは必ず最終段で答えを開示する。** 開示しない段で止めると
    「正解しないと進めない」が行き止まりになる。`Hint.next()` は段数を超えて
    呼ばれても最終段に留まる（呼び出し側の clamp に頼らない）。
    **1段目に「足りない観点の名前」を出す作りに戻さない。** 答えに近づかない足踏みで、
    受講者から「ヒントになっていない」と言われて捨てた段。いまの1段目は著者の誘導そのもの。
11. **選択肢の正解は `choices` の先頭。** 位置ではなく**文言**で照合する
    （`Choice.isCorrect`）。表示順はラリーごとに `Choice.order()` で混ぜているので、
    添字で判定すると必ず壊れる。
12. **飛ばした問題を評価の分母から外さない。** 外すと飛ばすほど点が上がる。
    `Grade.isDone()` は「正解した」と「飛ばした」の両方を数える。
13. **`pick()` を「最安の1問を必ず返す」に戻さない。** そうすると同じ条件から
    毎回まったく同じ問題が出る（実際にそうなって「毎回同じ問題が出ている」と指摘された）。
    最安から `RANDOM_WINDOW` 以内は同点とみなしてランダムに選ぶ。
    ただし**ランダムにするのは同じレベルの中だけ**。段を跨いで混ぜると
    「レベルに応じて難易度が変わる」が崩れる。
14. **`mode: 'level'` で段を外さない。** 選んだ段の未出題が残っているかぎり、
    その段からしか出さない（`pick(..., { strict: true })`）。
    借りるのは本当に出し切ったときだけ。ここを緩めると、
    L1を選んでもL3が混ざって「レベル別」が名前だけになる。
15. **`attempts` を `pick()` まで通す。** 最近解いた問題を後ろに回す上乗せ
    （`PICK_COST.recent` / `RECENT_DAYS`）はこれが無いと効かない。
    `create()` → `session.attempts` → `nextPick()` → `pick()` の経路を切らない。
13. **検査は `js/author/validate.js` の1か所だけ。** lint も、講師画面も、生成サーバーも
    ここを呼ぶ。片方だけ緩めると「lint は通るのにアプリが弾く」（またはその逆）が起きる。
14. **読めないものを読めたことにしない。** `extract()` は何として読んだか（`kind`）と
    怪しさ（`warnings`）を必ず返し、画面はそれをそのまま出す。空文字を黙って返さない。

## 採点の形（core/judge.js）

```
正解 = required のすべての観点で、any のどれか1語が入力に含まれる
```

照合は2段構え。基本形（NFKC → 小文字化 → 記号除去）で見て、外れたら
緩めた形（ひらがな→カタカナ、長音除去）でもう一度見る。
**当たった語（`matched`）を戻り値に残す。** 画面の「なぜ正解なのか」はこれを表示している。

## 出題選定の形（core/rally.js）

決め方は3つ（`MODES`）。**おまかせ以外ではレベルの階段を動かさない**。

1. `composePlan()` … おまかせ。履歴から単元を順位付けし、主単元と補単元を決める
2. `nextLevel()` … おまかせのみ。前問の結果だけで段を上下する（+1 / ±0 / −1、1〜5でclamp）
3. `pick()` … `|レベル差| × 3 + 単元コスト` が最小の未出題を出す
4. `reviewOrder()` … 復習。飛ばした → 答えを見た → ヒントが多い → 古い、の順に並べ直す

**狙い（`targetLevel`）と実際に出る問題のレベル（`level`）は別物。**
その段を出し切ると近い段から借りるので、10問だと後半は必ずずれる。
テストで階段を確かめるときは `targetLevel` を見る（`level` を見ると環境依存で落ちる）。

`Rally.create(bank, history, seed)` は **bank オブジェクトを受け取る**（id ではない）。
セッションは `session.bank` に参照を持つ。講師が作った問題集も同じ道を通るので、
ここに「同梱の問題集を id で引く」ような近道を作らない。

**選定理由は必ず record に残す（`pickReason` / `levelRule`）。**
画面はこれを表示しているので、残さないと「なぜこの問題か」が説明できなくなる。

## 問題を書くとき／生成するときの決まり

- **レベルは「難しそうか」でなく「問われている行為」で決める**（`Banks.LEVELS`）。
- **同梱の問題集は単元ごとに L1〜L5 を2問ずつ（計50問）揃える**
  （lint が `requireFullLevels` で段の欠けを見る）。
  1段につき1問だと `pick()` に選ぶ余地が無く、ランダム化を入れても同じ問題が出続ける。
  各段10問あることが「レベル別で10問ぜんぶその段」を成り立たせている。
  2問目の id は1問目に `b` を足したもの（`java-eq-1` に対する `java-eq-1b`）。
  講師が資料から作ったものは揃わないのが普通なので、そちらは警告どまり。
- **必須観点は最大3つ。** 4つ以上は「言い忘れ探し」になる。
- **設問文に答えの語を書かない。** 検査が落とす。同梱ぶんでも実際に3問漏らして書き直した
  （`java-eq-2` の `str.equals`、`java-exc-3` の `unchecked / RuntimeException`、
  `java-oop-3` の「親クラス型」）。
- **ヒントにも答えの語を書かない。** 生成側は `maskTerms()` で伏せてから出す。
  単元名に答えの語が混じる場合がある（「1. 機密区分」と答え「区分」）ので、単元名も伏せる。
- **1文字や2文字の候補語は避ける。** 部分一致なので、関係ない文に紛れて誤って当たる。
- **`why` と `source` を必ず書く。** `why` は「なぜこの観点を必須にしたか」であって、
  模範解答の言い換えではない。
- **選択肢は先頭が正解、残りは誤答。** 同梱ぶんは全問に付ける（lint の `requireChoices`）。
  誤答は「もっともらしいが確かに誤り」であること。実在の固有名詞を誤答にするときは、
  それが本当に誤りだと確かめる（`kw-sng-3` で「マンピーのG★SPOT」を稲村ジェーン関連として
  必須語に入れてしまっていた。選択肢を書く段で食い違いに気づいて直した）。

## 資料からの生成（author/generate.js）

芯は **「資料の一文を根拠として固定する」**。

```
模範解答 = 資料のその一文そのもの
必須観点 = その一文が成り立つために欠かせない語（設問文に出てこないものだけ）
出典     = ファイル名 / 単元名
```

作文した正解を混ぜないための形。テストが「模範解答が資料に実在すること」を見張っている。

- 語の切り出しは形態素解析なし。**漢字とカタカナが続くひとかたまりを1語にする**
  （分けると「情報システム部」が「情報」と「システム」に割れ、どちらも薄い語になる）。
- **達成基準と出題方針の語は重みを上げる**（`weighTerms` の boost）。これが「制御」の実体。
- **誤答の選択肢も資料の中から採る**（`buildChoices`）。作文した誤答は、もっともらしくても嘘になる。
  採点基準に照らして「正解になってしまう誤答」は外す（選択式と記述式で答えがずれないように）。
- **総合問題（達成基準そのもの）の必須観点は、達成基準に出てこない語から採る。**
  設問に達成基準の文を載せるので、達成基準の語を必須にすると設問を写すだけで通る。
- **穴埋めは単元あたり2問まで。** どんな文からでも作れてしまうので、
  抑えないと型の当たった良い問題より先に枠を埋める。

## 評価のパラメータは測って決める

- 減点表は **[1.0, 0.7, 0.45]**。ヒントを5段から3段に減らしたときに測り直した
  （1段の重みが大きくなるので、5段のときの表をそのまま使うと甘くなる）。
- 加点の上限は **0.05**。0.1 にすると「毎問ヒント1回＋加点満額」が A の下限に届いてしまう。
- レベル重みの差は **最大2倍**（L1=0.8 / L5=1.6）。開きすぎると
  低レベルの取りこぼしが評価に出なくなる。
- 閾値を触ったら `gradeOf(s.min)` が必ずその評価を返すことと、
  `toNext()` の差分を足すと実際に上がることの両方を確かめる（テストがある）。

## テストの構成

| 種別 | 場所 | 実行 | 内容 |
| --- | --- | --- | --- |
| 静的検査 | `tests/lint.mjs` | 依存不要 | 構文・参照・import の到達性・同梱問題集の健全性 |
| ロジック | `tests/logic/*.test.mjs` | `node --test` | 採点・ヒント・評価・出題選定・読み取り・生成・永続化 |
| ブラウザ | `tests/e2e/*.spec.mjs` | Playwright | ログイン・進行・しくみパネル・講師の作問・レイアウト |

### テストを書くときの注意

- **`js/` は直接 import する。** ES モジュールにしたので vm は要らなくなった
  （以前は realm をまたぐ `deepEqual` で嵌まっていた）。
- **浮動小数を直接比較しない。** `0.7 + 0.05` は `0.7500000000000001`。
  `scoreOne()` は小数3桁で丸めているので、期待値も丸めた値（`0.75`）で書く。
- **「どの問題も出題されうる」の検査は、順調な人だけで回さない。**
  全問一発正解だと段が上がる一方で、L1 に一度も触れない。
- **「わざと間違える」補助は、誤答が尽きたら前に選んだ誤答をもう一度選ぶ。**
  正解に落ちると「間違え続ける」テストが成立しない（実際にこれで取り違えた）。
- **`Store.useStorage()` はモジュール全体の状態を差し替える。** 同じファイル内のテストは
  順番に走る前提で書く（`node --test` はファイルごとに別プロセスなので、ファイルを跨ぐ心配はない）。
- **バイナリのフィクスチャはリポジトリに置かない。** `tests/logic/fixtures.mjs` が
  docx / pptx / xlsx / zip をその場で組み立てる。
- **Node の Buffer は Shift_JIS を書き出せない。** 文字コードのテストはバイト列を直接置く。
- **ブラウザを取得できない環境では `PW_CHROMIUM` に実行ファイルのパスを渡す。**
  この環境では `npx playwright install` が使えない。CIは自分で入れるので未設定でよい。
- **E2E は `ctx.errors` が空であることまで見る。** 講師画面が起動時に `/api/status` を
  叩いていたとき、これで 404 を捕まえた（いまは Claude を選んだときだけ調べる）。

## 過去の失敗と、繰り返さないためのルール

- **テスト結果は `0 failed` を明示的に確認する。** passed の件数だけを見て判断しない。
- **スマホ幅で選択肢が画面外に落ちた。** ヘッダ・進行の枠・対話ログのどれが伸びても起きる。
  `tests/e2e/layout.spec.mjs` が「問題文と最初の選択肢がファーストビューに入る」ことを
  検査しているので、上に何かを足すときは `.chat { max-height }` と
  `.rally-title p` の行数クランプを必ず見直す。
- **進行の枠は10個並ぶ。** 折り返さないと狭い画面で横スクロールが出る（`.steps` は `flex-wrap`）。
- **問題のレベル表示を本文に回り込ませない。** `float: right` にしていたら、
  狭い画面で問題文に重なった。見出しの行に入れる。
- **`span` は既定で inline。** 結果画面の棒グラフが伸びなかった原因。
  幅や高さを効かせたい要素には `display:block` を書く。
- **文書のタイトル行を単元にしない。** 見出しだけで中身の無い節を残すと、
  その単元が次の節の中身を食べて、単元名と中身がずれる。
- **手で確認したことはテストとして残す。** 「一度動いた」より「壊れたら気づける」を優先する。
- **出題がランダムかどうかは、実際に何回か回して確かめる。** 「乱数を入れた」では足りない。
  `tests/logic/rally.test.mjs` の「同じ条件でも、ラリーごとに出る問題が変わる」が
  6回中5通り以上を要求している。
- **事実を扱う問題集（桑田佳祐・サザンオールスターズ）は、記憶で書かない。**
  発売日・年号・担当楽器は `source` に書ける確度のものだけを採用する。
- **合言葉を認証と呼ばない。** クライアントに平文で置く以上、目隠しでしかない。
  画面にもそう書いてある。書き換えない。
