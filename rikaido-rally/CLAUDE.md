# CLAUDE.md — 理解度アップ・テストラリー

記述式5問の理解度テスト。**ビルド不要・実行時依存ゼロ**の単体Webアプリ。
`index.html` をブラウザで開けばそのまま動く。

## 構成

```
index.html          マークアップ。<script> の並び順が依存関係そのもの
css/style.css       テーマ・レイアウト
js/judge.js         記述式の採点（正規化と照合。他に依存しない）
js/grade.js         A〜E の評価（減点表・レベル重み・閾値。他に依存しない）
js/hint.js          ヒントの段階（judge の戻り値を読む）
js/banks.js         問題集の登録所とレベルの定義
js/bank-java.js     問題集：Java の落とし穴（純データ）
js/bank-kuwata.js   問題集：桑田佳祐とサザンオールスターズ（純データ）
js/rally.js         単元の自動生成・レベルの階段・出題選定・進行（制御の本体）
js/storage.js       localStorage 永続化
js/render.js        DOM 描画。rally/judge/grade/hint に依存
js/main.js          進行役とUIバインド。上記すべてに依存
tests/              テスト
```

## 開発コマンド

```bash
npm ci && npm test   # lint → ロジック → E2E
npm start            # http://127.0.0.1:8082/
```

CI はリポジトリ直下の `.github/workflows/ci.yml`（3アプリを回す）。
**サブディレクトリ配下の `.github/workflows/` は GitHub では実行されない**。

## 壊してはいけない設計上の制約

1. **実行時の依存パッケージをゼロに保つ。** ビルド工程を持ち込まない。
   Playwright は開発時のみの依存で、配信物には含めない。
2. **ESモジュールを使わない。** `file://` で直接開いた時に CORS で失敗するため、
   各ファイルは即時関数で `window.RR` 名前空間に公開するクラシックスクリプトにする。
   したがって **`index.html` の script の順序が依存関係**（`npm run lint` が検査する）。
3. **`localStorage` は必ず try/catch で包む。** 読み書きの両方が例外を投げうる。
4. **設定キーは必ず `Store.DEFAULTS.settings` に定義する。** 定義漏れのキーは
   `merge()` で捨てられ、保存しても復元されない。
5. **乱数を直接呼ばない。** `Rally.seededRandom(seed)` を通す。`?seed=` で再現するため。
6. **`[hidden] { display: none !important; }` を消さない。**
   `.btn` などの display 指定が既定の `[hidden]` に勝ち、隠したボタンが出たままになる。
7. **正規化で `=` と `+` を落とさない（`Judge.STRIP`）。**
   落とすと `==` が空文字になり、`contains()` が**何にでも一致する**。
   Java の等価性の単元がまるごと無意味になる。`contains()` の空 needle ガードは必ず残す。
8. **正誤は必須観点だけで決める。** 加点観点と誤解検出を正誤に混ぜない。
   混ぜると「加点を拾ったから通った」という説明のつかない正解が生まれ、
   画面の根拠表示（`.evidence`）が嘘になる。
9. **説明文を render.js に書き足さない。** 『しくみ』パネルは
   `Rally.UNIT_RULES` / `LADDER_RULES` / `PICK_COST` / `Judge.RULE_TEXT` /
   `Grade.SCALE` / `Hint.STAGES` を**そのまま表に起こしている**。
   ここに手書きの説明を足すと、定数を変えたときに説明だけが古くなる。
10. **ヒントは必ず最終段で模範解答を開示する。** 開示しない段で止めると
   「正解しないと進めない」が行き止まりになる。`Hint.next()` は段数を超えて
   呼ばれても最終段に留まる（呼び出し側の clamp に頼らない）。

## 採点の形（Judge.evaluate）

```
正解 = required のすべての観点で、any のどれか1語が入力に含まれる
```

照合は2段構え。基本形（NFKC → 小文字化 → 記号除去）で見て、外れたら
緩めた形（ひらがな→カタカナ、長音除去）でもう一度見る。
**当たった語（`matched`）を戻り値に残す。** 画面の「なぜ正解なのか」はこれを表示している。
ここを消すと根拠が出せなくなる。

## 出題選定の形（Rally）

1. `composePlan()` … 履歴から単元を順位付けし、主単元と補単元を決めてラリー名を組み立てる
2. `nextLevel()` … 前問の結果だけで段を上下する（+1 / ±0 / −1、1〜5でclamp）
3. `pick()` … `|レベル差| × 3 + 単元コスト` が最小の未出題を出す

**選定理由は必ず record に残す（`pickReason` / `levelRule`）。**
画面はこれを表示しているので、残さないと「なぜこの問題か」が説明できなくなる。

## 問題を書くときの決まり

- **レベルは「難しそうか」でなく「問われている行為」で決める**（`Banks.LEVELS`）。
  L1=再生 / L2=説明 / L3=使い分け / L4=予測 / L5=判断。
- **単元ごとに L1〜L5 を1問ずつ揃える。** 欠けると階段が組めず、
  狙いと違う段の問題が出る（lint が落とす）。
- **必須観点は最大3つ。** 4つ以上にすると、正しく理解している人でも
  言い落としで不正解になり、ヒントが「言い忘れ探し」に変わる（lint が落とす）。
- **設問文に答えの語を書かない。** `tests/logic/banks.test.mjs` が
  「設問文をそのまま貼り付けて正解になるか」を検査している。
  実際に3問（`java-eq-2` の `str.equals`、`java-exc-3` の `unchecked / RuntimeException`、
  `java-oop-3` の「親クラス型」）でこれを漏らし、書き直した。
- **1文字や2文字の候補語は避ける。** 部分一致なので、関係ない文に紛れて誤って当たる。
  どうしても必要なら（`java-str-4` の「3」など）、他の必須観点と組で使う。
- **`why` と `source` を必ず書く。** 画面に出る。
  `why` は「なぜこの観点を必須にしたか」であって、模範解答の言い換えではない。
- **誤解検出（traps）は正誤を動かさない。** 必須観点と同じ語を入れない（lint が落とす）。

## 評価のパラメータは測って決める

- 加点の上限は **0.05**。0.1 にすると「毎問ヒント1回＋加点満額」が
  ちょうど 90点＝A の下限になり、伴走してもらった人が A に届いてしまう。
  テスト（`grade.test.mjs` の「毎問ヒント1回で加点を満額取っても A には届かない」）で捕まえて下げた。
- レベル重みの差は **最大2倍**（L1=0.8 / L5=1.6）。開きすぎると
  低レベルの取りこぼしが評価に出なくなる。
- 閾値を触ったら `gradeOf(s.min)` が必ずその評価を返すことと、
  `toNext()` の差分を足すと実際に上がることの両方を確かめる（テストがある）。

## テストの構成

| 種別 | 場所 | 実行 | 内容 |
| --- | --- | --- | --- |
| 静的検査 | `tests/lint.mjs` | 依存不要 | 構文・参照・読み込み順・問題データ・採点基準の健全性 |
| ロジック | `tests/logic/*.test.mjs` | `node --test` | 採点・ヒント・評価・出題選定・問題集の不変条件・永続化 |
| ブラウザ | `tests/e2e/*.spec.mjs` | Playwright | 対話の進行・しくみパネル・レイアウト |

### lint が見ている「データの健全性」

普通の lint と違い、**採点基準そのものの正しさ**を機械的に確かめている。

- 模範解答は、自分の採点基準で必ず正解になる（＝ヒントの終点が行き止まりでない）
- 空文字・「わかりません」等では、どの問題も正解にならない（＝全一致する候補語が無い）
- 誤解検出の語が必須観点と重なっていない
- 単元ごとに L1〜L5 が揃っている
- どの段のヒントも空にならず、最終段は必ず開示になる

**問題を足したら必ず `npm run lint` を通す。** 実際にこの検査で、
模範解答が自分の基準を通らない問題を2件（`java-oop-4` / `java-oop-5`）捕まえている。

### テストを書くときの注意

- **vm の中の配列を `assert.deepEqual` で比べない。** realm が違うので
  「構造は同じだが参照が違う」で落ちる。`Array.from(...).join(',')` などで比べる。
- **浮動小数を直接比較しない。** `0.8 + 0.05` は `0.8500000000000001` になる。
  `scoreOne()` は小数3桁で丸めているので、期待値も丸めた値（`0.85`）で書く。
- **「どの問題も出題されうる」の検査は、順調な人だけで回さない。**
  全問一発正解だと段が `2→3→4→5→5` にしか進まず、L1 に一度も触れない。
  詰まる人（誤答1回・2回）も回して初めて全問に届く。
- **ブラウザを取得できない環境では `PW_CHROMIUM` に実行ファイルのパスを渡す。**
  この環境では `npx playwright install` が使えない。CIは自分で入れるので未設定でよい。

## 過去の失敗と、繰り返さないためのルール

- **テスト結果は `0 failed` を明示的に確認する。** passed の件数だけを見て判断しない。
- **スマホ幅で回答欄が画面外に落ちた。** ヘッダと対話ログが伸びると送信ボタンが
  ファーストビューから出る。`tests/e2e/layout.spec.mjs` が検査しているので、
  上に何かを足すときは `.chat { max-height }` を必ず見直す。
- **手で確認したことはテストとして残す。** 「一度動いた」より「壊れたら気づける」を優先する。
- **事実を扱う問題集（桑田佳祐・サザンオールスターズ）は、記憶で書かない。**
  発売日・年号・担当楽器は `source` に書ける確度のものだけを採用する。
  怪しいものは問題にしない。
