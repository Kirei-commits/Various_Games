# 理解度アップ・テストラリー（RIKAIDO RALLY）

記述式で5問。**正解するまで進めず、間違えるたびにヒントが一段ずつ具体的になります。**
評価は A〜E。ヒントを使うほど下がるので、同じ単元を繰り返して A に上げていく作りです。

`index.html` をブラウザで開けばそのまま動きます（サーバー不要・ビルド不要・実行時の依存ゼロ）。

同梱の問題集は2つです。

| 問題集 | 単元 | 問題数 |
| --- | --- | --- |
| Java の落とし穴 | 等価性と比較 / 文字列の扱い / コレクションの選択 / 例外の扱い / 継承と多態 | 25 |
| 桑田佳祐とサザンオールスターズ | 生い立ちと結成 / 代表曲と作品 / メンバーと担当 / ソロと別プロジェクト / 活動の節目 | 25 |

---

## 1. 達成基準 — 何をもって「正解」とするか

正解の条件は1つだけです。

```
正解 = 必須観点のすべてで、その観点が認める語のいずれか1語が回答に含まれること
```

- **加点観点**と**誤解検出**は、正誤を一切動かしません。加点は評価点にだけ、誤解検出はヒントの出し分けにだけ使います。
- 必須観点は1問につき最大3つ。レベルが上がるほど増やしています（L1は1つ、L5は2〜3つ）。

例：`java-eq-1`（`new String("neko")` どうしを `==` で比べると？）

| 種別 | 観点 | 認める語 |
| --- | --- | --- |
| 必須 | 結果 | false / 偽 / ならない / なりません |
| 必須 | 理由 | 参照 / アドレス / 別のインスタンス / 同一性 / インスタンスが違… |
| 加点 | 中身は同じ | equals / 中身は同じ / 内容は同じ |
| 誤解 | 値で比べている | true / 同じだから |

「false です」だけでは通りません。**結果と理由の両方**が要ります。
逆に「参照が違うので一致しません」は、言い方が模範解答と違っても通ります。

### 表記ゆれの吸収

照合の前に、回答と候補語の両方を同じ手順で正規化しています。

```
NFKC正規化 → 小文字化 → 空白・句読点・括弧を除去
（それで外れたら）ひらがな→カタカナ → 長音を除去 して、もう一度照合
```

これで `ＥＱＵＡＬＳ です。` も `equals` に、`えりー` も `エリー` に、`メンバ` も `メンバー` に当たります。

**`=` と `+` は除去しません。** 除去すると `==` が空文字になり、
「何にでも一致する候補語」ができてしまうためです（Javaの等価性の問題がまるごと壊れます）。

### なぜこの基準で正解と言えるのか

問題データには、模範解答のほかに次の2つを必ず持たせています。画面では正解した瞬間に開きます。

- `why` … **なぜその観点を必須にしたのか**。「ここが言えていないと次の問題が説明できない」という理由。
- `source` … 出典・確認先（言語仕様の項番、Javadoc、発売日など）。

さらに、データの正しさは静的検査が機械的に見ています（`npm run lint`）。

- 模範解答は、**自分の採点基準で必ず正解になる**こと（＝ヒントの終点が行き止まりにならない）
- 空文字や「わかりません」では、**どの問題も正解にならない**こと（＝全一致する候補語が紛れ込んでいない）
- **設問文をそのまま貼り付けても正解にならない**こと（＝問題が答えを漏らしていない）
- 誤解検出の語が、必須観点の語と重なっていないこと

## 2. 制御 — 正解するまで進めない仕組み

```
出題中 ──(不正解)──> ヒント中 ──(不正解)──> ヒント中 ── … 
   │                      │
   └──(正解)──> 正解・解説 ──(次へ)──> 出題中 … ×5 ──> 評価
```

**問題番号が進むのは「正解」だけ**です。ヒント中から抜ける道は正解しかありません。
行き止まりにならないよう、ヒントは5段目で模範解答を開示します。

| 段 | 種類 | 出すもの |
| --- | --- | --- |
| 1 | 観点 | 足りない観点の**名前だけ**（＋誤解を検出していればその指摘） |
| 2 | ヒント1 | 問題ごとに用意した誘導 |
| 3 | ヒント2 | さらに絞り込む誘導（用意が無ければ4段目へ繰り上げ） |
| 4 | 頭出し | 不足語を `e○○○○○（6文字）` の形で見せる |
| 5 | 模範解答 | 開示。読んだうえで自分の言葉で書き直して通過（最低点） |

1段目で観点の**名前**しか出さないのは、いきなり語を見せると考える余地が消えるからです。
`tests/e2e/rally.spec.mjs` が「1段目に答えの語が混ざっていないこと」を検査しています。

## 3. 評価 — A〜E の出し方

受講者は必ず正解するので、正誤では差がつきません。差がつくのは
**何回のヒントで辿り着いたか**と、**どのレベルの問題でそれをやったか**の2つだけです。

```
問題ごとの到達点 = 減点表[使ったヒント数] (+ 加点観点のぶん、最大 +0.05)
理解度スコア     = Σ(到達点 × レベル重み) / Σ(レベル重み) × 100
レベル重み       = 0.6 + 0.2 × レベル   （L1=0.8 … L5=1.6。差は最大2倍）
```

| ヒント | 0回 | 1回 | 2回 | 3回 | 4回以上 | 模範解答を見た後 |
| --- | --- | --- | --- | --- | --- | --- |
| 到達点 | 1.0 | 0.8 | 0.6 | 0.45 | 0.3 | 0.15 |

| 評価 | 下限 | 状態 |
| --- | --- | --- |
| **A** | 90 | 説明できる — ほぼ自力。人に教えられる状態 |
| **B** | 75 | 概ね掴んでいる — 要所は出てくる。言葉の精度が課題 |
| **C** | 60 | 心当たりはある — ヒント1つで思い出せる。定着が浅い |
| **D** | 40 | 断片的 — 誘導が要る。用語と理由が結びついていない |
| **E** | 0 | これから — 初見に近い。まずは1周して言葉に触れる |

加点のぶんを **+0.05** に抑えてあるのは、0.1 にすると
「毎問ヒント1回＋加点満額」がちょうど90点になり、**伴走してもらった人が A に届いてしまう**ためです
（実際にテストで検出して下げました）。

結果画面には「A まであと何点か」と、**失点の大きい順**に並べた弱点（レベル×取りこぼし）が出ます。

## 4. 出題の選定 — 単元の自動生成とレベルの階段

### 単元は毎回その場で決める

ラリーを始めるたびに、履歴から単元の順位を作り直します。

1. まだ一度も出していない単元を最優先する
2. 直近の理解度スコアが低い単元を次に優先する
3. 同点なら、最後にやってから間が空いている方を選ぶ

1位が**主単元**、2位が**補単元**。ラリー名はこの2つから組み立てます
（例：`代表曲と作品 ＋ ソロと別プロジェクト（補）`）。
**苦手な単元が自動で回ってくる**ので、放っておいても弱点から埋まっていきます。

### レベルは前問の結果で上下する

1問目は **レベル2**（説明）から。1にすると全員が満点付近に寄って差が出ません。

| 前問の結果 | 動き |
| --- | --- |
| ヒント0回で正解 | **+1**（一発で当てた → 1段上げる） |
| ヒント1回で正解 | **±0**（少し詰まった → 同じ段でもう一問） |
| ヒント2回以上、または模範解答を見た | **−1**（手が止まった → 1段下げて土台を固める） |

全問一発正解なら `2 → 3 → 4 → 5 → 5`。詰まると下がっていきます（下限1・上限5）。

### 問題はコストで選ぶ

```
選定コスト = |狙いのレベル − 問題のレベル| × 3 ＋ 単元（主 0 / 補 1 / 他 4）
```

最小のものを出します。主単元にその段の未出題が残っていればそれを出し、
出し切っていれば補単元の同じ段から借ります（だから5問目の2回目のL5は補単元から来ます）。

### レベルの決め方

「難しそうか」ではなく、**問われている行為**で決めています。

| Lv | 名前 | できること | 問いの形 |
| --- | --- | --- | --- |
| 1 | 再生 | 用語や事実を思い出せる | 「〜は何か」「誰か」「何年か」 |
| 2 | 説明 | 仕組みを自分の言葉で言える | 「なぜそうなるか」「何が起きるか」 |
| 3 | 使い分け | 条件によって答えが変わると分かる | 「どんなときに」「違いは」 |
| 4 | 予測 | 具体例の結末を当てられる | 「このコードは」「この場合どうなる」 |
| 5 | 判断 | トレードオフや背景を語れる | 「どちらが正しいか、何を壊すか」 |

単元ごとに L1〜L5 を1問ずつ揃えてあります（`npm run lint` が欠けを検出します）。

## 5. 画面の「しくみを見る」

上の内容は、アプリの右側のパネルにそのまま出ます。
**説明文を別に持たず、動いているコードの定数と戻り値を表示している**ので、コードと説明がずれません。

| パネル | 中身 |
| --- | --- |
| 1. このラリーの組み立て | 単元の順位表・選定理由・レベルの階段（予定と実際）・この問題が選ばれた理由 |
| 2. いまの問題の採点基準 | 必須／加点／誤解の観点と認める語・達成基準の式・正規化の手順 |
| 3. 直前の判定ログ | 入力 → 正規化後の文字列 → 観点ごとの当たり外れと一致した語 → 充足率 |
| 4. 評価の出し方 | 減点表・レベル重み・問題ごとの内訳・現在の暫定スコアと次の評価までの差 |
| 5. 進行の制御 | 状態機械の現在地・ヒントの段階表・いまの試行回数 |
| 6. 問題レベルの決め方と品揃え | レベルの定義表・単元×レベルの充足表 |

「認める語」は、受講者モードでは正解するまで伏せます。
上部の**講師モード**（または `?teacher=1`）で先に開示できます。

### URL パラメータ

| パラメータ | 意味 |
| --- | --- |
| `?bank=java` / `?bank=kuwata` | 問題集を指定 |
| `?seed=123` | 出題の並びを固定（再現用） |
| `?teacher=1` | 講師モードで開く |

## 6. 問題集を足す

`js/bank-*.js` を1つ作って `index.html` に読み込むだけです。
エンジン（judge / hint / grade / rally）は題材を一切知りません。

```js
RR.Banks.register({
  id: 'your-bank', name: '表示名', subtitle: '…', blurb: '…',
  units: [{ id: 'u1', label: '単元名', summary: '…', levelNote: 'レベルの配り方の説明' }],
  questions: [{
    id: 'u1-1', unit: 'u1', level: 1,
    prompt: '設問文',
    criteria: {
      required: [{ key: '観点名', any: ['認める語', '言い換え'], why: 'なぜ必須か' }],
      optional: [{ key: '…', any: ['…'] }],
      traps:    [{ key: '…', any: ['…'], hint: '誤解を指摘する文' }]
    },
    hints: ['1つ目の誘導', '2つ目の誘導'],
    model: '模範解答', why: 'この基準にしている理由', source: '出典'
  }]
});
```

書いたら `npm run lint`。単元ごとの L1〜L5 の欠け、模範解答が自分の基準を通らない、
設問が答えを漏らしている、といった不備はここで落ちます。

## 開発

```bash
npm ci && npm test   # lint → ロジック → ブラウザ
npm start            # http://127.0.0.1:8082/
```

| 種別 | 場所 | 実行 | 内容 |
| --- | --- | --- | --- |
| 静的検査 | `tests/lint.mjs` | 依存不要 | 構文・参照・読み込み順・問題データの整合・採点基準の健全性 |
| ロジック | `tests/logic/*.test.mjs` | `node --test` | 採点・ヒント・評価・出題選定・永続化 |
| ブラウザ | `tests/e2e/*.spec.mjs` | Playwright | 対話の進行・しくみパネル・レイアウト（デスクトップ＋スマホ） |

ブラウザを取得できない環境では `PW_CHROMIUM` に実行ファイルのパスを渡してください。
CI はリポジトリ直下の `.github/workflows/ci.yml` です。
