# 理解度アップ・テストラリー（RIKAIDO RALLY）

**えらんで答える10問。** まちがえるとヒントが3段階で出て、それでも分からなければ飛ばせます。
評価は A〜E。ヒントを使うほど下がるので、同じところを繰り返して A に上げていく作りです。

スマホで最後まで解けることを優先していて、**既定ではキーボードを出しません**。
書いて答えたい人のために記述式も残してあり、画面上部の「キーボードで書いて答える」で切り替わります。

**講師は、手持ちの資料からテストを作れます。** 資料を読み込ませ、達成基準と出題方針を書くと、
そこから選択式の問題が組み上がります。作った問題は、同梱のテストとまったく同じ検査を通ったものだけが出題されます。

`index.html` をブラウザで開けば動きます（ビルド不要・実行時の依存ゼロ）。
ES モジュールを使っているので、`file://` ではなく `npm start` で開いてください。

| 画面 | できること |
| --- | --- |
| ログイン | 受講者 / 講師 を選ぶ |
| 受講者 | テストを受ける。採点の根拠・出題の決め方・評価の出し方をその場で見られる |
| 講師 | 資料からテストを作る。達成基準と出題方針で制御する。作ったテストの書き出し・読み込み |

同梱のテストは2つです（講師が作ったものと並んで、受講者の画面から選べます）。

| テスト | 単元 | 問題数 |
| --- | --- | --- |
| Java の落とし穴 | 等価性と比較 / 文字列の扱い / コレクションの選択 / 例外の扱い / 継承と多態 | 25（全問4択） |
| 桑田佳祐とサザンオールスターズ | 生い立ちと結成 / 代表曲と作品 / メンバーと担当 / ソロと別プロジェクト / 活動の節目 | 25（全問4択） |

## 0. 1問の流れ

```
問題が出る
  ├ 正しい選択肢を選ぶ ───────────────> 根拠と解説が開く → 次の問題へ
  ├ まちがえる → ヒント1（手がかり）
  │             → ヒント2（誤答を1つ消す）
  │             → ヒント3（答えを開示）    → 選び直して次へ
  └ 「わからない（答えを見る）」を押す ──> 答えと解説が開く（0点）→ 次の問題へ
```

飛ばした問題は 0 点ですが、**答えと解説はきちんと出ます**。
そして「復習（過去に出た問題）」で真っ先に出し直されます。飛ばし得にはしません。

## 1. 達成基準 — 何をもって「正解」とするか

### 選択式（既定）

```
正解 = 選んだ文言が、データの choices の先頭と一致すること
```

**データの規約として `choices` の先頭が正解**です。表示の順番はラリーごとに混ぜるので、
「いつも2番目」のような位置では当たりません（問題を書く側は並べ替えを気にしなくて済みます）。

### 記述式（「キーボードで書いて答える」にしたとき）

```
正解 = 必須観点のすべてで、その観点が認める語のいずれか1語が回答に含まれること
```

- **加点観点**と**誤解検出**は、正誤を一切動かしません。加点は評価点にだけ、誤解検出はヒントの出し分けにだけ使います。
- 必須観点は1問につき最大3つ。4つ以上にすると、理解している人でも言い落としで不正解になり、テストが理解度を測らなくなります。

例：`java-eq-1`（`new String("neko")` どうしを `==` で比べると？）

| 種別 | 観点 | 認める語 |
| --- | --- | --- |
| 必須 | 結果 | false / 偽 / ならない / なりません |
| 必須 | 理由 | 参照 / アドレス / 別のインスタンス / 同一性 / インスタンスが違… |
| 加点 | 中身は同じ | equals / 中身は同じ / 内容は同じ |
| 誤解 | 値で比べている | true / 同じだから |

「false です」だけでは通りません。**結果と理由の両方**が要ります。
逆に「参照が違うので一致しません」は、言い方が模範解答と違っても通ります。

### 表記ゆれの吸収

照合の前に、回答と候補語の両方を同じ手順で正規化しています。

```
NFKC正規化 → 小文字化 → 空白・句読点・括弧を除去
（それで外れたら）ひらがな→カタカナ → 長音を除去 して、もう一度照合
```

これで `ＥＱＵＡＬＳ です。` も `equals` に、`えりー` も `エリー` に、`メンバ` も `メンバー` に当たります。

**`=` と `+` は除去しません。** 除去すると `==` が空文字になり、
「何にでも一致する候補語」ができてしまうためです（Javaの等価性の問題がまるごと壊れます）。

### なぜこの基準で正解と言えるのか

問題データには、模範解答のほかに次の2つを必ず持たせています。画面では正解した瞬間に開きます。

- `why` … **なぜその観点を必須にしたのか**。「ここが言えていないと次の問題が説明できない」という理由。
- `source` … 出典・確認先（言語仕様の項番、Javadoc、発売日、資料のどの節か）。

さらに、データの正しさは `js/author/validate.js` が機械的に見ています。
**同梱の問題集も、講師が資料から作った問題集も、まったく同じ関数を通ります。**

- 模範解答は、**自分の採点基準で必ず正解になる**こと（＝ヒントの終点が行き止まりにならない）
- 空文字や「わかりません」では、**どの問題も正解にならない**こと（＝何にでも一致する候補語が紛れ込んでいない）
- **設問文をそのまま貼り付けても正解にならない**こと（＝問題が答えを漏らしていない）
- 誤解検出の語が、必須観点の語と重なっていないこと
- どの段のヒントも空にならず、最終段は必ず模範解答を開示すること

## 2. 制御 — 進み方

```
出題中 ──(まちがえる)──> ヒント中 ──(まちがえる)──> ヒント中 ── …
   │                        │
   │                        └──(正解)──> 正解・解説 ┐
   ├──(正解)──────────────────────────────────────┤
   └──(わからない)──────────> 飛ばした ────────────┴─> 次の問題 … ×10 ──> 評価
```

**問題番号が進むのは「正解した」か「飛ばした」かのどちらか**です。
まちがえただけでは進みません。ヒントは3段目で必ず答えを開示するので、行き止まりにはなりません。

| 段 | 名前 | 出すもの |
| --- | --- | --- |
| 1 | 手がかり | 問題ごとに用意した誘導をそのまま出す |
| 2 | しぼる | 選択式は**誤答を1つ消す**／記述式は不足語を `e○○○○○（6文字）` の形で頭出し |
| 3 | 答え | 正解を開示する |

1段目から中身のある手がかりを出します。以前は「足りない観点の名前」を出していましたが、
答えに近づかないただの足踏みだったのでやめました（`tests/e2e/rally.spec.mjs` が、
1段目に観点の羅列が戻っていないことを検査しています）。

## 3. 評価 — A〜E の出し方

正解するまで進めないので、正誤そのものでは差がつきません。差がつくのは
**何回のヒントで辿り着いたか**（または飛ばしたか）と、**どのレベルの問題でそれをやったか**です。

```
問題ごとの到達点 = 減点表[使ったヒント数] (+ 加点観点のぶん、最大 +0.05)
理解度スコア     = Σ(到達点 × レベル重み) / Σ(レベル重み) × 100
レベル重み       = 0.6 + 0.2 × レベル   （L1=0.8 … L5=1.6。差は最大2倍）
```

| | ヒント0回 | 1回 | 2回 | 答えを見た | 飛ばした |
| --- | --- | --- | --- | --- | --- |
| 到達点 | 1.0 | 0.7 | 0.45 | 0.15 | 0 |

ヒントが3段しかないぶん、1段の重みは以前より大きくしてあります。
**飛ばした問題も評価に数えます**（分母から外すと、飛ばすほど点が上がってしまうため）。

| 評価 | 下限 | 状態 |
| --- | --- | --- |
| **A** | 90 | 説明できる — ほぼ自力。人に教えられる状態 |
| **B** | 75 | 概ね掴んでいる — 要所は出てくる。言葉の精度が課題 |
| **C** | 60 | 心当たりはある — ヒント1つで思い出せる。定着が浅い |
| **D** | 40 | 断片的 — 誘導が要る。用語と理由が結びついていない |
| **E** | 0 | これから — 初見に近い。まずは1周して言葉に触れる |

加点（書いて答えるときだけ）を **+0.05** に抑えてあるのは、0.1 にすると
「毎問ヒント1回＋加点満額」が A の下限に届いてしまうためです。

## 4. 出題の選定 — 3つの決め方

画面上部の「出題」で切り替えます。

| 決め方 | 中身 |
| --- | --- |
| **おまかせ** | 弱い単元から選び、出来に合わせてレベルを上げ下げする |
| **レベル別** | 選んだレベル（1〜5）の問題だけを10問出す |
| **復習** | これまでに出た問題を、飛ばした順・詰まった順に出し直す |

### おまかせ：単元は毎回その場で決める

1. まだ一度も出していない単元を最優先する
2. 直近の理解度スコアが低い単元を次に優先する
3. 同点なら、最後にやってから間が空いている方を選ぶ

1位が**主単元**、2位が**補単元**。ラリー名はこの2つから組み立てます
（例：`代表曲と作品 ＋ ソロと別プロジェクト（補）`）。**苦手な単元が自動で回ってきます。**

### おまかせ：レベルは前問の結果で上下する

1問目は **レベル2**（説明）から。1にすると全員が満点付近に寄って差が出ません。

| 前問の結果 | 動き |
| --- | --- |
| ヒント0回で正解 | **+1**（一発で当てた → 1段上げる） |
| ヒント1回で正解 | **±0**（少し詰まった → 同じ段でもう一問） |
| ヒント2回以上・答えを見た・飛ばした | **−1**（手が止まった → 1段下げて土台を固める） |

全問一発正解なら狙いは `2 → 3 → 4 → 5 → 5 …`。
実際に出る問題は、その段を出し切ると近い段から借りるので、狙いと一致するとは限りません
（結果画面には狙いと実際の両方が出ます）。

### レベル別

その段の問題を出し切ったら、いちばん近い段から借りて10問を埋めます。
同梱のテストは単元ごとに L1〜L5 が1問ずつなので、どの段でも5問は必ずその段から出ます。

### 復習

前に出た問題だけが対象です。並べ替えの順番はこの通り。

1. 「わからない」で飛ばした問題を最優先する
2. 次に、答えを見て通した問題
3. 次に、ヒントを多く使った問題
4. 同じなら、最後に解いてから間が空いている方

まだ1問も解いていないときは選べません（おまかせに落ちて、その理由が画面に出ます）。

### 問題はコストで選ぶ（おまかせ）

```
選定コスト = |狙いのレベル − 問題のレベル| × 3 ＋ 単元（主 0 / 補 1 / 他 4）
```

### レベルの決め方

「難しそうか」ではなく、**問われている行為**で決めています。

| Lv | 名前 | できること | 問いの形 |
| --- | --- | --- | --- |
| 1 | 再生 | 用語や事実を思い出せる | 「〜は何か」「誰か」「何年か」 |
| 2 | 説明 | 仕組みを自分の言葉で言える | 「なぜそうなるか」「何が起きるか」 |
| 3 | 使い分け | 条件によって答えが変わると分かる | 「どんなときに」「違いは」 |
| 4 | 予測 | 具体例の結末を当てられる | 「このコードは」「この場合どうなる」 |
| 5 | 判断 | トレードオフや背景を語れる | 「どちらが正しいか、何を壊すか」 |

## 5. 講師：資料からテストを作る

### 読み込めるファイル

拡張子で読み方を決めます。追加のライブラリは使っていません（ZIP の展開は `DecompressionStream`、
文字コードの判別は `TextDecoder` に任せています）。

| 形式 | 読み方 |
| --- | --- |
| `.txt` `.md` `.log` `.srt` `.vtt` ほかテキスト | そのまま。UTF-8 / Shift_JIS / EUC-JP / UTF-16 を判別します |
| `.csv` `.tsv` | 1行を1文にまとめます |
| `.json` `.jsonl` | 文字列と数値を、キーを添えて拾います |
| `.html` `.xml` `.svg` | タグを落として本文だけにします |
| `.docx` `.pptx` `.xlsx`（`.odt` `.odp` `.ods` も） | ZIP を展開して本文を取り出します。docx は段落、pptx はスライド順、xlsx は共有文字列表を引きます |
| `.zip` | 中の読めるものを全部つなげます（読めなかったものは警告に出ます） |
| `.pdf` | テキストが埋まっていれば拾います。**日本語の埋め込みフォントは化けることがあるので、必ず抽出結果を目で確かめてください** |
| そのほか | まずテキストとして読み、化けていれば理由を出して止めます |

読み込んだ本文はそのまま編集できます。ファイルが読めない資料でも、本文を貼り付ければ同じように作れます。

### 達成基準と出題方針で制御する

- **達成基準** … この資料を読んだ人に何ができていてほしいか。
  ここに書いた語は**重みが上がり**、その語を含む文が優先して出題されます。
  さらに達成基準そのものが、**最後の総合問題（レベル5）**になります。
- **出題方針** … どう問うてほしいか。Claude で作るときはそのまま指示になり、
  この端末で作るときは重視する語として効きます。

### 作り方は2通り、そのあとの道は1本

| 作り方 | 中身 | 要るもの |
| --- | --- | --- |
| **この端末で作る**（既定） | 資料の一文を根拠として固定し、定義・理由・条件・対比・手順・穴埋めの型に当てはめます。**模範解答も誤答の選択肢も資料の中から採る**ので、作文された正解や、もっともらしい嘘の誤答が混ざりません | 何も要りません |
| **Claude に作らせる** | 資料・達成基準・出題方針を Claude に渡し、採点エンジンの仕様つきで作らせます。問い方の自由度が高くなります | 手元で生成サーバーを立てること |

どちらで作っても、**そのあとは同じ検査（`js/author/validate.js`）を必ず通ります。**
通らなかった問題は捨て、理由を画面に出します（検査を緩めるくらいなら問題数が減る方がよい、という判断です）。

### Claude に作らせるとき

```bash
ANTHROPIC_API_KEY=... npm run studio
# → http://127.0.0.1:8082/ を開いて、講師 → 作り方を「Claude に作らせる」
```

**API キーはこのサーバーの中にしか置きません。** ブラウザには渡しません。
静的サイトから直接 Anthropic を叩く作りにすると、ページを開いた全員に鍵が配られます。
そのため GitHub Pages で開いたときは Claude 経路は使えず、画面もそう表示します。

既定のモデルは `claude-opus-5`（`RR_MODEL` で変えられます）。
断られたときに別モデルへ回す server-side fallback を既定で有効にしてあります。

### 作ったテストの扱い

- 保存先はこのブラウザの `localStorage` だけです。サーバーには送られません。
- **JSON で書き出し／読み込み**ができます。別の端末の講師に渡すときはこれを使ってください。
- 読み込んだ JSON も検査を通ります。通らなければ理由を出して取り込みません。

### ログインについて（正直に）

役割の選択と、講師用の合言葉があります。合言葉はこの端末に平文で保存され、
ページのコードから読めます。**同席者への目隠しであって、認証ではありません。**
本当に秘匿したい内容を、この画面に入れないでください。

## 6. 画面の「しくみを見る」

上の内容は、受講者の画面の右側にそのまま出ます。
**説明文を別に持たず、動いているコードの定数と戻り値を表示している**ので、コードと説明がずれません。

| パネル | 中身 |
| --- | --- |
| 1. このラリーの組み立て | 出題の決め方3つ・単元の順位表・レベルの階段（予定と実際）・この問題が選ばれた理由 |
| 2. いまの問題の採点基準 | 選択肢とその正誤・必須／加点／誤解の観点と認める語・正規化の手順 |
| 3. 直前の判定ログ | 選んだもの（記述式なら入力 → 正規化後 → 観点ごとの当たり外れ）と判定 |
| 4. 評価の出し方 | 減点表・レベル重み・問題ごとの内訳・現在の暫定スコアと次の評価までの差 |
| 5. 進行の制御 | 状態機械の現在地（飛ばしも含む）・ヒントの段階表・いまの試行回数 |
| 6. 問題レベルの決め方と品揃え | レベルの定義表・単元×レベルの充足表 |

「認める語」は、受講者モードでは正解するまで伏せます。上部の「採点基準を先に開示」で先に見られます。

### URL パラメータ

| パラメータ | 意味 |
| --- | --- |
| `?role=learner` / `?role=teacher` | ログイン画面を飛ばす |
| `?bank=java` / `?bank=kuwata` / `?bank=<作ったテストのid>` | テストを指定 |
| `?mode=auto` / `level` / `review` | 出題の決め方 |
| `?level=1`〜`5` | レベル別のときの段 |
| `?style=choice` / `text` | えらんで答える／書いて答える |
| `?seed=123` | 出題の並びを固定（再現用） |
| `?criteria=1` | 採点基準を先に開示した状態で始める |

## 開発

```bash
npm ci && npm test   # lint → ロジック → ブラウザ
npm start            # http://127.0.0.1:8082/（静的配信のみ）
npm run studio       # 同じポートで、Claude 生成の API 付き
```

```
index.html              3つの画面（ログイン / 受講者 / 講師）
css/style.css           明るいテーマ
js/main.js              起動と画面の出し分け
js/core/                採点・ヒント・評価・出題選定・保存（題材を知らない）
js/data/                同梱の問題集（純データ）
js/author/              資料の読み取り・問題の生成・検査
js/ui/                  画面
tools/studio.mjs        講師用のローカルサーバー（Claude 生成。任意）
```

| 種別 | 場所 | 実行 | 内容 |
| --- | --- | --- | --- |
| 静的検査 | `tests/lint.mjs` | 依存不要 | 構文・参照・import の到達性・同梱問題集の健全性 |
| ロジック | `tests/logic/*.test.mjs` | `node --test` | 採点・ヒント・評価・出題選定・資料の読み取り・問題の生成・永続化 |
| ブラウザ | `tests/e2e/*.spec.mjs` | Playwright | ログイン・対話の進行・しくみパネル・講師の作問・レイアウト |

ブラウザを取得できない環境では `PW_CHROMIUM` に実行ファイルのパスを渡してください。
CI はリポジトリ直下の `.github/workflows/ci.yml` です。
