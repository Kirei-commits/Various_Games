## 3. 設計を変えた点

### 3.1 そのままだと動かない・壊れるもの

- **`assets/` フォルダ**：リポジトリ直下に小文字の `assets/index.json` を置く設計だった。Windows と macOS は大文字小文字を区別しないので、Unity の `Assets/` と同じフォルダになる。`ledger/assets.json` に移した。
- **素材とデータの実行時の読み込み**：台帳の `path`（`Assets/Art/...`）は、ビルド後は読めない。エディタ拡張が台帳から `AssetCatalog`（ID→参照の表）を作る形にした。マスタJSONも同じで、`DataManifest` から読む。
- **dotnet と Unity の両方でコンパイルする条件**：dotnet 側を netstandard2.1・C# 9 に固定する。固定しないと、dotnet では通って Unity で通らないコードが入る。
- **JSON Schema の検証**：dotnet 側だけにした。Unity 側は型への厳格な読み込みと、C# で書いた検証で代える。
- **キャラ JSON の「正」**：前は「手で JSON を直さず、毎回 Importer を通す」だった。Importer の入力（`dev/キャラデータ.md`）はコミットしないファイルなので、数値の正がリポジトリの外にあることになる。取り込みは一度きりにし、その後は JSON を正にした。

### 3.2 敵の強さの決め方

仕様書6.2節は、敵1体の戦力PからHP＝0.89P・攻撃力＝0.031P と、味方の比率で割り振る。ランク15で概算すると、

- 味方のクリティカル：発生率 75−15＝60％、倍率 (9,000−5,400)÷100＝36倍。与ダメージは平均で約22倍。
- 推奨戦力Rの7体の通常攻撃だけで、毎秒 0.031R × 2.88回 × 22 ≒ 2R。
- ボスのHPは 0.89 × 0.48R ≒ 0.43R。

ボスは約0.2秒で倒れる。制限時間60秒の戦闘にするには、HPを100倍前後にする必要がある（必殺スキルと防御を無視した概算。正確な値はシミュレーションで出す）。逆に敵の攻撃は、味方1体（HP 約0.13R）を数秒で倒す強さがある。

そこで、ランクごとのHP倍率・攻撃力倍率（`enemyScale`）を difficulty.json に持ち、`Mado.Sim calibrate` が「推奨ちょうどで勝率80％、ボス戦の決着まで20〜40秒」になる値を自動で求めるようにした。仕様書の式そのものは残してある。敵の攻撃スピードも未定義だったので、1.0（仮）を置いた。

### 3.3 作る順番

- **図鑑・コレクション・リーダー特殊ツリーをフェーズ5から4へ**。仕様書6.4節の全体倍率はこの3つ（合計+29,000％）を含む。フェーズ4で全ランクの勝率を合わせるので、ステータスに効く育成がそろっていないと、合わせた係数がフェーズ5でずれる。
- **`sim_profiles.json`**：ランクごとの「標準的に育てた状態」をシミュレーション用の表にした。経済ができる前（フェーズ1〜4）の戦闘バランスは、この表を前提に測る。
- **キャラ付与はデバッグ用コマンド**。前は「開発者モードのキャラ付与」と書いてあったが、仕様書7.9節の開発者モードは素材が減らないだけの機能。分けた。

### 3.4 Core の構造

- **Meta を4つに分けた**（Session／Growth／Progress／Economy）。15機能が1つの名前空間にあると、互いに直接呼び合って直しにくくなる。
- **Battle は育成を知らない**。入力は解決済みの BattleSetup だけ。これを JSON に書き出せる形にし、決定性テストの入力に使う。
- **ステータスの集め方**：各育成機能が `IModifierSource` を実装し、StatResolver は集まった Modifier を合成するだけ。機能を足しても StatResolver は変わらない。
- **累計の数え上げは1か所**（MetricCounter）。実績・パス・レース・図鑑が同じ数を読む。
- **読み取り専用の窓**（GameState）。イベントだけでは、画面を開いた瞬間の値が取れない。
- **Wallet**：複数通貨のまとめ払い（全部か無しか）、負の数・NaN の拒否、個数の通貨は整数に丸める。
- **RepeatGate**：繰り返せる収入の歯止めを、試練ごとの `cooldownSec` ではなく共通の型にした（要確認の1）。

### 3.5 テスト

- **決定性テストの入力を固定の BattleSetup にした**。マスタから毎回組み立てると、数値を1つ変えるたびに全ハッシュが変わり、仕組みが壊れたのか数値を変えただけなのか見分けられない。数値の変化は別のスナップショットで見る。
- **決定性の範囲を決めた**：「同じ実行環境で同じ結果」。Editor・dotnet・実機の間でビット単位の一致は求めない。
- **依存の向きのテスト**と、**通貨の行き来の検証**（入手できない通貨、使い道のない通貨を見つける）を足した。

### 3.6 データの型

- キャラデータの語彙を数えて、型に足りなかったものを足した：下級、無敵、反射、解除の向き（味方のデバフ／敵のバフ）、挑発、失ったHPに応じた追加ダメージ、「HP50％以下で一度だけ」。
- 編成を用途ごとに持てるようにした（vs竜は属性ごとに組み替えるため）。リーダーは全編成で共通。
- 攻撃スピードを Modifier にした（研究ツリーで上げる案と、記憶カードだけの案のどちらでも持てる）。
- 通貨に、覚醒の欠片・使い魔の特殊能力の素材・霊界の広場の素材を足した。霊石版と記憶カードは通貨ではなく持ち物にした。
- マスタから消えたIDがセーブに残っていても落とさない。
