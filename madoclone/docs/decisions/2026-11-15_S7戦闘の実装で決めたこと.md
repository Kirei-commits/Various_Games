# 2026-11-15 S7〜S8（戦闘・ゴールデン）の実装で決めたこと

docs/04 に書かれていなかった細部を、実装で次のように決めた（外れたら該当箇所を直す）。いずれも `[仮]`。

- **攻撃の進行度**：0.1 を10回足しても 1.0 に届かない誤差があるので、`>= 1.0 - 1e-9` で判定する。1秒間隔の攻撃は10刻み目に出る。
- **トリガーの順番**：キューは**積んだ順（FIFO）**で処理する。同じ刻みの「通常→特殊→必殺→魔晶」は、ユニットの処理順と枠の順に積まれるので、結果として守られる。種類ごとに並べ替えはしない。
- **効果の確率**：`chancePct` が 100 以上の効果は判定しない（乱数を引かない）。トリガーの確率（onHit・onDamaged）は 100 でも必ず引く。
- **onHit・onCrit きっかけのスキル**：きっかけの相手には「命中済み（onCrit ならクリティカル済み）」の記録を最初から入れる。そうしないと、ダメージ効果を持たない特殊スキルの `when: afterHit` が永久に成り立たない。
- **無敵の対象への攻撃**：命中・クリティカルの記録を「外れ」にする（`when: afterHit` の効果は付かない）。
- **敵の専用スキル**：まだ無い。`StageFactory` が作る敵は、単体攻撃の通常スキルだけを持つ（タンクの挑発などはフェーズ1の後半）。
- **`sim_profiles.json`**：型とスキーマ・空のファイルだけ作った（`SimProfiles.Load` は DataLoader とは別。ゲーム本体は読まない）。`globalMultiplier` の計算と `calibrate` は 2026-11-16 に実装した（`2026-11-16_calibrateの結果と所見.md`）。
- **C# の validate**：`Mado.Sim validate` を作り、`tools/bootstrap/compare_validate.py`（正しいデータと6通りの壊し方）で Python 版と合否が一致することを `check.sh` で毎回確かめる。ただし Python 版にしか無い検査（キャラ105体・ボス推奨戦力の表・元作品の名前）があるので、**Python 版は残す**（置き換えは、C# 側へ移してから）。
- **ゴールデンの敵**：味方の合計戦力 × 倍率（2.5〜5）で作る。味方は全体強化なしの基礎値のままなので、docs/01 6.2節の見直しのとおり、敵の戦力を「推奨」から決めると桁が足りない。calibrate が入るまでの暫定の倍率（calibrate 後も、ゴールデンの setup は解決済みなので変わらない。スナップショットだけ更新した）。
