# 2026-11-16 記憶カード・放置報酬の仮の数値の検証

実装（フェーズ2の記憶カード・放置報酬）に入る前に、`docs/01` の仮の数値が実測値と矛盾しないかを計算で確かめた（計算は下の表。再現は `tools/bootstrap/` の Python で数行）。

## 結果
| 確かめたこと | 結果 |
| --- | --- |
| 実測の記憶カード8枚が「％ ＝ 係数 ×（カードLv＋3）」に合うか | **合う**。係数は UR=3.75、UR+=5.0〜5.5、スピードカード UR=1.25（実測が 3.7500／5.2500／5.5000／5.0000／1.2500／1.5000 ぴったり） |

| 6.4節「記憶カード +2,400％」の根拠 | EX Lv160 のメイン％ 7.25×163＝1,182％が2枚で 2,364％。**合う** |

## 見つけた食い違い（決めたこと）
1. **固定値は単位を直さないと、基礎ステータスを何百倍も超える**。実測の固定値（UR・HP カード Lv108 で +2,726,882）は、**全体強化が乗った後の単位**。`stat_tables.json` の基礎表（Lv1 の HP 8,500）の単位に足すと 321 倍になる。
   → 固定値は「実測の Lv1（全体強化込み）に対する、基礎表の Lv1 の比」で換算する：HP ×5.424e-4、攻撃 ×4.047e-4、防御 ×3.046e-4。UR・HP カード Lv108 は +1,479（Lv1 の基礎 HP の 17％）になり、妥当な大きさ。この換算係数と、固定値の係数（HP UR 221.3・UR+ 783.2／攻撃 UR 11.47・UR+ 20.27／防御 8.0）は Data に置く。
2. **カードLvの上限**。6.4節は「EX Lv160」だが、絆ガチャの最大Lvは 140（確定）で、カードLvは絆ガチャLvと同じと推定されている。→ **カードLvの上限は絆ガチャの最大Lv（140）にする**。EX の2枚は +2,074％（6.4節の 2,400％より小さい）。6.4節の表は次の実装で直す。
3. **スピードカードの HP・攻撃・防御％（EX Lv140 で 1枚 +340％）は、6.4節の予算に入っていない**。2枚で約 +680％だが、全体倍率（約74万倍）に対して 0.1％以下なので、予算の表は直さず、注記だけ足す。
4. **攻撃スピード**：EX のスピードカード2枚（Lv140）で 4.7 倍。`system.attackSpeedMax`（5.0）に収まる。UR・Lv108 の2枚は 2.67 倍で、実測メモの「約3倍が上限の目安」と合う。

## 経験値（ユーザー回答：敵を倒すと経験値がドロップする。量は任せる）
- 経験値は**通貨 `exp`**（敵を倒すとドロップ、放置報酬でも貯まる）。キャラのレベルアップで払う（`stat_tables.json` の `expToNext`。Lv1→50 で累計 84.6M、実測と一致）。
- 敵1体あたりの量は、ランクごとの表（`rewards.json` の `expPerEnemy`）を **`Mado.Sim rewards` が計算して書く**（手で書かない）。決め方：そのランクで標準編成が「想定★／Lv」まで育つのに要る経験値を、ランクボス到達までの撃破数（100 ステージ × 15 体）で割り、余裕（`paceSlack` = 1.25）を掛ける。ランクごとの「育つ量」は、同じ★が続くランクで等分する。
- 放置報酬（実測：毎分 32 万）は、ステージの進みに合わせて、この敵1体あたりの量から計算する（次のコミット）。
