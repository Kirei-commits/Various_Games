# 2026-11-16 リファクタリングとテストの強化

S2〜S8 を一気に作ったあと、いったん品質を固めた。ゴールデンのハッシュ・calibrate の結果は、どちらも変わっていない（挙動を変えずに整理した）。

## 測り方
- `scripts/coverage.sh`：Core と Data のカバレッジ（coverlet）。下限は行 96％・分岐 91％（いまは 98.7％・93.9％。始める前は 93.3％・85.0％）。
- テストが本当に効くかは、本体をわざと壊して確かめた（戦闘不能の相手にダメージが入るようにする → 不変条件テストとゴールデンが落ちる）。

## 足したテスト（170 → 264件）
- `DataValidatorCodeTests`：検査1つにつき、実データを1か所壊して期待する Code が出ること（表）。`DataValidator.cs` に書かれた Code を表がすべて覆っていることも確かめる（検査を足して表を忘れると落ちる）。
- `BattleInvariantTests`：実データからランダムに組んだ300戦で、HP の範囲、生死とイベントの一致、与ダメージの合計、勝敗と生存の一致、警告が出ないこと、決定性。
- `BattleSimEdgeTests`：使い方の誤り、イベントの上限、cleanse／dispel、持続回復、同率の回復対象、属性での絞り込み、DOT での撃破、ほか。
- `SmallPartsTests`・`DataPrimitivesTests`・`SimPolicyTests`：小さな部品の境目と、誤った使い方。

## 見つけて直したもの
- **イベントが上限（20万件）に達しても、警告が出ていなかった**（設計では警告を出す）。警告を1件出し、以後は記録しないが、`BattleEnd` は必ず出すようにした。
- **戦闘不能のユニットに、バフが付くことがありえた**（onDeath のスキルが自分にバフを付ける形）。戦闘不能のユニットには何も付けない、に統一した。いまのデータには該当が無く、ゴールデンは不変。

## 整理したもの
- `BattleSim.RunSkill`：準備（主対象・スナップショット・人数補正・命中の記録）を名前のある関数に分けた。トリガーをキューに積む同じ形のループ3つを `EnqueueTriggers` に。
- `DamageCalc.Damage`：同じ型の引数10個を、名前付きの `DamageInput` に（取り違えを防ぐ）。
- 「標準編成を組む」処理が calibrate・テスト・ゴールデンに別々にあったのを、`ProfilePartyFactory` と `BattleSetupBuilder.OwnCrystalLoadout` にまとめた。calibrate の static な可変フィールドをやめ、`Calibrator` クラスにした。
- 固有魔晶の枠の番号「2」が3か所に直書きだったのを、`CharacterState.OwnCrystalSlot` に。
- `Wallet.Grant` の端数の繰り越しを `TakeWhole` に。`StageFactory` の敵の種類の文字列を定数に。
- テスト側：実データの探し方が3か所に重複していたのを `TestData` に。使われていないコードを削除。
- `check_sources.py`：Battle は Save も参照しない、Wallet・Save は戦闘・育成を参照しない、を追加。

## 分かったこと（直していない）
- 対象の生存チェックは「対象を選ぶ所」「効果を適用する所」「ダメージを与える所」の3層にあり、1つ外してもテストは落ちない（3つとも外すと落ちる）。安全側の重複なので残した。
- `Ranked<T>` は読み込み専用（書くと読み戻せない形になる）。戦闘用のデータ（`BattleSetup`）に `Ranked` を入れない前提を、テストで固定した。
