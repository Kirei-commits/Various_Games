# 2026-11-16 経済シミュレーション（`Mado.Sim economy`）と覚醒の欠片

## 何をしたか
- **覚醒の費用**：そのキャラの**余ったコピー**を先に使い、足りない分を覚醒の欠片で払う（docs/01 7.1節の置き換え）。失敗ではコピーも減らない。
- **欠片の確定ドロップ**：敵1体を倒すと `rewards.json` の `awakenShardPerEnemy` だけ落ちる（0.3。整数の通貨なので端数は繰り越す）。
- **試練を3つ足した**：合同討伐（ギルドコイン）、闘技大会（魔闘ポイント）、大書庫（研究メモ・絆ハート）。ショップの交換所に通貨が流れる。解放ランクは [仮]。
- **経済シミュレーション**：`dotnet run --project tools/Mado.Sim -- economy [--minutes 120]`。遊び手（`EconomyBot`）が GameSession の公開コマンドだけで、毎分：雑魚戦1回・ボス戦1回、5分ごとに放置報酬、レベル上げ・覚醒・編成の入れ替え・ガチャ（10連）・解放済みの試練。機能の解放は本物。育成の出どころの代用は `RankProfileSource`（MadoHost と同じ）。

## 結果（開始時チケット30枚、2時間）
| 項目 | 結果 |
| --- | --- |
| 最大★ | 30分で★2、60分で★3、**90分で★6**、120分で★6（完了条件「1〜2時間で★6魔晶まで届く」を満たす） |
| 編成の平均Lv | 2時間で約27（ランク1の上限Lv 50 まで届かない） |
| ランク | 2時間でランク1の途中（1分1ステージのボス戦で、ランク1の100ステージに約100分） |

## 決めたこと・気づき
- **最初のチケットは30枚**（300枚だと重複コピーで10分で★9に届き、早すぎた）。MadoHost の初期付与も30枚に揃えた。
- 欠片のドロップを 0.03 → 0.1 → **0.3** と上げて、90分で★6に届く値にした。0.1 では2時間で★3だった。ステージ・試練での確定ドロップが主な収入で、これ以上増やすと★上げが早すぎる。
- 完了条件のテスト：`tests/Sim/EconomyBotTests.cs`（2時間で★6、10分では★6でない、決定的）。経済の数値を変えて落ちたら、`economy` を流して値を合わせ直す。
- **未検討**：ジェムの収入（バトルラッシュはランク1ではまだ勝てない）、コインの使い道（絆ガチャLv）、放置報酬の24時間貯め込みを含めた1日単位の見積もり。
