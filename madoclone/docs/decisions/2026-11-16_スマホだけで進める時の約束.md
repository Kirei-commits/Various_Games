# 2026-11-16 スマホだけで進めるときの約束

- **決めたこと**：ユーザーは当面 PC を使わない（スマホのチャットだけで進める）。仕様と設計は残したまま、ここ（クラウドのセッション）でできる実装を進める。
- **できること／できないこと**：この環境には dotnet・mono・csc が無く、NuGet にも届かないので、**C# はコンパイルも実行もできない**。Unity も動かせない。Python・Node は使える。
- **やり方**：(1) コードは設計書（docs/04）のスライス順に、テストと一緒に書く。(2) コンパイルの代わりに、`tools/bootstrap/check_csharp.py` で「C# の型が実データを受け付けるか」「括弧の釣り合い」を確かめ、`check_sources.py` で不変条件を確かめる。(3) 計算の中身（Wallet・戦闘など）は、Python の鏡（参照実装）で期待値を作ってテストに入れる（Rng と同じやり方）。(4) 最初にコンパイルできる環境が手に入ったら、**まず `dotnet build` と `dotnet test` を流してコンパイルエラーを直す**。コンパイルエラーは機械的に直せるが、論理の誤りはテストが見つける。
- **コンパイルできる環境を手に入れる方法**（どれか）：①PC（Claude Code）②アカウントの設定でセッションのネットワークを許可（`api.nuget.org`・`dot.net`・`builds.dotnet.microsoft.com`・`dotnetcli.azureedge.net` などの許可が要る）して、新しいチャットで `dotnet` を入れる ③GitHub の非公開リポジトリに置いて、GitHub Actions で `dotnet test` を流す（スマホから結果を見られる）。
- **Unity が要る部分（View・アセット・APK のビルド）** は S9 以降。クラウドだけで完結させるなら、GameCI（GitHub Actions）で APK をビルドする方法がある（Unity の個人ライセンスの登録が要る）。必要になったら別の決定記録で決める。
- 理由：Core・Data・Sim は Unity に依存しない設計なので、ゲームの中身の大半は dotnet だけで作ってテストできる。
