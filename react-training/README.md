# React アプリ設計・実践研修（全4回）

前提知識ゼロから、**「どこに・どんなファイルを作ればいいか」を自分で決められるようになる**ための教材アプリです。
専門用語は使わず、レストランと部屋の片付けにたとえて、1回分ずつ進めます。

`index.html` をブラウザで直接開けば動きます（サーバー不要）。

| 回 | テーマ | 内容 |
|---|---|---|
| 第1回 | アプリの全体像をつかむ | 3つの役割（🙋 ホールスタッフ＝コンポーネント / 🍳 キッチン＝カスタムフック / 🚚 仕入れ業者＝API）。仕分け練習つき |
| 第2回 | フォルダの分け方 | 種類別と機能別を、アプリの大きさを切りかえて比較。最小構成のフォルダツリー、受付窓口（index.ts）、shared の使い方 |
| 第3回 | 実際のコードを見てみる | 「お買い物メモ」の悪い例（1ファイル）と良い例（3ファイル）を動かして見比べる。分け方の手順、読みこみの向き、仕入れ業者を差しかえるテスト |
| 第4回 | 実践演習 | 自分のアプリの機能と形（一覧 / 送る / 画面の中だけ）を入力すると、フォルダ構成図とひな形コードができあがる |

1回分は5〜7個の短いパートに分かれています。各回に次の解説が付いています。

- **なぜこうするのか**（設計の理由と、分けすぎないための判断基準）
- **コードを見るときのポイント**（どのファイルから、どこを見るか）
- **レビューチェックリスト**（チェックは保存されます）
- **よくある失敗と見分け方**（見分け方・なぜ困るか・直し方）
- **つまずいたら（よくある質問）**
- **理解度チェック**（選択クイズ＋ミニ課題。ヒントと模範解答つき。選択肢の並びは問題ごとにまぜてあります）

前の回のクイズとミニ課題を終えると、次の回が開きます（ページ下の設定で、全部を自由に読めるようにもできます）。
進み具合・書いた答え・設計図は、ブラウザの localStorage に保存されます。
開いている回とパートはページの住所（`#/2/3` = 第2回のパート3）に入るので、ブラウザの「戻る」が効き、開き直しても同じ場所から読めます。

元の指示書は「AI と対話しながら進める」形ですが、このアプリは決まった文章とクイズで進む読み物です。
質問への受け答えや、ミニ課題の自動採点はありません（模範解答と自分で見比べます）。

## 開発

```
npm ci
npm run dev        # 開発サーバー（src/ をそのまま動かす）
npm run build      # src/ を1枚の index.html にまとめる（変更したら実行して、index.html もコミットする）
npm run lint       # index.html が今の src/ から作られたものか確かめる（依存なしで動く）
npm run test:logic # 型チェック + ロジックテスト（Vitest）
npm run test:e2e   # ブラウザテスト（Playwright。コミット済みの index.html を開いて確かめる）
npm test           # 上の3つをまとめて
```

`src/` を変えたのに `npm run build` を忘れると、`npm run lint` が落ちます（CI でも同じ）。

## このアプリ自体の構成

教えている形（機能ごとのフォルダ＋3つの役割）で、このアプリも作っています。

```
src/
├─ app/                       入口とページ。機能を並べ、引き合わせる
│   ├─ App.tsx                回とパートを切りかえる
│   ├─ useRoute.ts            いま開いている回を、ページの住所で覚える
│   └─ lessons/               第1〜4回の本文（lessonN/PartN.tsx と data.ts）
│       └─ widgets.tsx        クイズと「進み具合の保存」を引き合わせる
├─ features/
│   ├─ quiz/                  クイズとミニ課題（見せるだけ。保存はしない）
│   ├─ checklist/             レビューチェックリスト（見せるだけ）
│   ├─ progress/              進み具合の保存（api / hooks / components）
│   ├─ shopping-list/         第3回の良い例（api / hooks / components の3ファイル＋フックのテスト）
│   ├─ shopping-list-bad/     第3回の悪い例（1ファイル）
│   └─ blueprint/             第4回の設計図づくり（api / logic / hooks / components）
└─ shared/
    ├─ components/            コード表示・構成図・囲み・見出しなど
    └─ lib/                   保存の道具、コードの色分け
```

守っているルールは `src/architecture.test.ts` が見張っています。

- 機能は、別の機能を読みこまない（引き合わせるのは `app`）
- `app` は、機能を受付窓口（`index.ts`）からだけ読みこむ
- `api` は React も `hooks`・`components` も読みこまない / `hooks` は `components` を読みこまない / `components` は `api` を呼ばない

第3回で表示しているコードは、`features/shopping-list*/` の実際のファイルを `?raw` で読みこんだものです。
説明と動いているコードがずれないように、コードを直すと表示も変わります。

## 内容を足す・直すとき

- 本文は `src/app/lessons/lessonN/PartN.tsx`、クイズ・チェックリスト・失敗例・よくある質問は同じフォルダの `data.ts` にあります。
- パートの並びは `lessonN/index.ts`。
- クイズやチェックリストの `id` を変えると、保存済みの答え・チェックは外れます。
- 問題を足して正解の位置が偏ると `src/app/lessons/lessons.test.ts` が落ちます。そのときは `features/quiz/logic/shuffle.ts` の `SALT` を変えます。
- ひな形コードの中身は `src/features/blueprint/logic/generateBlueprint.ts`（テストは同じフォルダの `.test.ts`）。
