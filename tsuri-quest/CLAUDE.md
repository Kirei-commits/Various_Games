# CLAUDE.md — つりクエスト（TSURI QUEST）

7種類の魚を釣ってレベルを上げる釣りゲーム。**ビルド不要・実行時依存ゼロ**の単体Webアプリ。
`index.html` をブラウザで開けばそのまま動く。

このディレクトリは `Various_Games` リポジトリの中のひとつのゲーム。
**CI はリポジトリ直下の `.github/workflows/ci.yml`** にあり、
ゲームを増やしたらそこの matrix にディレクトリ名を足す（後述）。

## 構成

```
index.html          マークアップ。<script> の並び順が依存関係そのもの
css/style.css       テーマ・レイアウト・アニメーション
js/fish.js          魚7種の定義と抽選（純粋。他に依存しない）
js/progress.js      ポイント計算とレベル（純粋）
js/world.js         時間帯と天候（純粋）
js/gear.js          竿・糸・エサの定義と購入判定（純粋）
js/achievements.js  実績と称号の判定（純粋）
js/storage.js       localStorage 永続化と、釣果を状態へ反映する処理
js/game.js          釣りの状態機械。fish に依存
js/audio.js         Web Audio API による効果音の合成
js/render.js        Canvas 描画。fish の配色に依存
js/main.js          UIバインドと進行。上記すべてに依存
tests/              テスト（下記）
```

`js/main.js` 以外は**DOMにもCanvasにも触らない**。だから状態機械もバランスも
ブラウザ抜きで Node のテストランナーだけで検証できる。この境界は崩さないこと。

## 開発コマンド

```bash
npm ci               # 開発用の依存（Playwright のみ）
npm start            # http://127.0.0.1:8081/ で配信（五目並べの8080と衝突させない）
npm run lint         # 構文・参照整合性・読み込み順・状態キーの定義漏れ
npm run test:logic   # 抽選・得点・状態機械・永続化・バランス
npm run test:e2e     # ブラウザテスト（desktop + mobile）
npm test             # 上記すべて
```

## 壊してはいけない設計上の制約

1. **実行時の依存パッケージをゼロに保つ。** ビルド工程を持ち込まない。
   Playwright は開発時のみの依存で、配信物には含めない。
2. **ESモジュールを使わない。** `file://` で直接開いた時に CORS で失敗するため、
   各ファイルは即時関数で `window.FQ` 名前空間に公開するクラシックスクリプトにする。
   したがって **`index.html` の script の順序が依存関係**であり、入れ替えると壊れる
   （`npm run lint` がこの順序を検査する）。
3. **乱数を直接呼ばない。** `Math.random()` は `main.js` の入口（`?seed=` が無いとき）
   だけ。それ以外は必ず引数か `create({ random })` で受け取る。
   これがないとバランス検証も状態機械のテストもフレーキーになる。
4. **時間も外から与える。** `game.tick(dt)` に経過時間を渡す形にしてあり、
   モジュール内で `Date.now()` / `performance.now()` を呼ばない。
5. **`localStorage` は必ず try/catch で包む。** プライベートモードでは読み書きの
   両方が例外を投げる。使えない場合も既定値で動作を継続する
   （`save()` は保存できたときだけ true を返す）。
6. **保存する状態のキーは必ず `Store.DEFAULTS` に定義する。** 定義漏れのキーは
   `merge()` で捨てられ、保存しても復元されない。`npm run lint` が
   `state.<key>` の出現と `DEFAULTS` を突き合わせて検出する。
7. **操作は「押す→離す」の1系統に統一する。** 端末による分岐を作らない。
   押した瞬間の意味だけがフェーズで変わる（キャスト／合わせ／巻き始め／結果を閉じる）。
   Canvas には `touch-action: none` が必要（押したままページがスクロールしないため）。
   `setPointerCapture` を使い、`blur` でも巻きを止める（指を外したまま止まらない事故を防ぐ）。
8. **道具の効果を混ぜない。** 竿＝取り込み速度と合わせの猶予、糸＝切れる限界、
   エサ＝待ち時間とレア／大物寄せ。ひとつで全部良くなると強化の選択が意味を失う。
   `tests/logic/gear.test.mjs` が「竿と糸の総コストが等しい」ことまで見ている。
9. **バランスの数字はテストで守る。** レベル曲線・重み・コストを触ったら
   `tests/logic/balance.test.mjs` が落ちる。落ちたら「バグ」ではなく
   「意図した変更かどうか」を判断し、意図的なら期待値を更新して理由をコミットに残す。

## テストの構成

| 種別 | 場所 | 実行 | 内容 |
| --- | --- | --- | --- |
| 静的検査 | `tests/lint.mjs` | 依存不要 | 全JSの構文、`index.html` の参照先、読み込み順、状態キーの定義漏れ |
| ロジック | `tests/logic/*.test.mjs` | `node --test` | 抽選・得点・レベル・時間帯と天候・道具・状態機械・実績・永続化・バランス |
| ブラウザ | `tests/e2e/*.spec.mjs` | Playwright | 一連の釣り・購入と強化・パネル・永続化・レイアウト・タッチ操作 |

E2Eは `desktop`（マウス）と `mobile`（Pixel 5 / `hasTouch`）の2プロジェクトで走る。
端末差は `tests/e2e/fixtures.mjs` に閉じ込め、スペック本体には分岐を書かない。
指での操作そのものの検証は `touch.spec.mjs` に集約し、
`test.skip(({ isMobile }) => !isMobile)` で mobile だけに限定する。

`balance.test.mjs` は**ゲームまるごとを再生する**。一人前のプレイヤーを模した
オートパイロットで数千キャストを回し、Lv30到達までのキャスト数・レア率の推移・
7種すべてに出会えるか・装備強化の効果を数値で確かめる。
調整の手戻りを防ぐいちばん重要なテスト。

## 過去の失敗と、繰り返さないためのルール

（五目並べ側の `../gomoku-narabe/CLAUDE.md` にある教訓も引き続き有効。
　ここには、このゲームを作る過程で新しく踏んだものだけを書く）

### 1. サブディレクトリに置いたワークフローは実行されない

**起きたこと**: `gomoku-narabe/.github/workflows/ci.yml` がこのリポジトリでは
一度も動いていなかった。GitHub Actions は**リポジトリ直下の `.github/workflows/` しか
読まない**。単独リポジトリから移設したときに気づかれず、CIが無いまま進んでいた。

**ルール**: モノレポではワークフローを**リポジトリ直下に1つ**置き、matrix で
サブディレクトリを回す。ゲームを足したら matrix にディレクトリ名を足す。
CI があること自体を、実行結果（conclusion）で確認する。

### 2. `hidden` 属性は作者スタイルの `display` に負ける

**起きたこと**: `.gauges { display: grid }` を書いたため、`hidden` 属性を付けても
ゲージが出っぱなしになっていた。UA スタイルシートの `[hidden] { display: none }` は
同じ詳細度の作者スタイルに負ける。E2Eの「ゲージはファイト中だけ出る」で発覚した。

**ルール**: 表示・非表示を `hidden` 属性で切り替えるなら、
CSS の先頭で `[hidden] { display: none !important; }` を一度だけ宣言しておく。
表示の切り替えは**E2Eで実際に見えているかを確かめる**（属性が付いていることの確認では足りない）。

### 3. 「効果があるはず」の検証は、効果が出る条件で測る

**起きたこと**: 「装備を強化すると成果が上がる」テストが、強化あり・なしで
まったく同じ結果になって落ちた。オートパイロットが完璧すぎて一度もバラさないため、
糸の強さも竿の速さも結果に現れなかった。

**ルール**: 強化の価値は**それが効く条件**で測る。
糸は「限界を考えずに同じ力で巻く荒いプレイヤー」でバラシ率の差として、
竿は「同じ魚を釣るのに要したファイト時間」の差として測っている。
テストが通らないときは、まず**測り方が現象を捉えているか**を疑う。

### 4. 数字の期待値を記憶で書かない

**起きたこと**: 「累計1234ポイントなら Lv8」とテストに書いたが、実際は Lv6 だった。
レベル曲線を頭の中で計算して決め打ちしていた。

**ルール**: 期待値は**式から導く**か、一度実行して確かめた値を書く。
決め打ちの数字を書くときは、その根拠になる計算もテスト内に置く。
